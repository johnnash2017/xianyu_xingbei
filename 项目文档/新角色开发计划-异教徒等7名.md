## 1. 通用约定（与《技能维护约定》一致，只列本轮特别注意的）

1. **数据只有设计表一个源**：角色表「脚本」列、卡表新增行都改 `Table/Design/设计表.xlsx`，再导表
   （`ExcelToCsv` → `CsvToGd`，可在无头下调用，见 1.1）。
2. **不用自己造“新区域”**：角色表「指示物」列里已经给这几个角色配好了槽位 ——
   `0:祭:3`、`0:裁决:3`、`0:圣印:2`、`2:卢恩:6`、`2:结界:2`、`2:妖力:2`。
   `0/1` 号槽＝普通指示物，**`2` 号槽＝盖牌区（cover_cards）**，所以【卢恩】【结界】【妖力】直接放盖牌区，
   用 `player.cover_cards` / `cover_cards_max` 管理，不要再造一套并行区域。
3. **【结界】要公开牌面**：盖牌默认对别人只显示张数。给盖牌区加了「面朝上」标记（F2），
   面朝上的盖牌把牌面写进快照（`covereds_open`），客户端在面板盖牌提示里显示。
4. **【异端裁决所】【末日预言】【绝界】是“场卡”**（不属于任何人的手牌/盖牌），统一走 F1 的场卡系统：
   引擎 `field_cards` + 快照 `field_cards` + 客户端在拥有者面板的状态区显示「名字 + 计数」。
5. **【魔刃】【异刃】是特殊卡**：走卡表新增两行（虚拟/特殊类型），拿到手后由角色脚本按“视为攻击牌”处理（F9）。
6. 不新增运行时区域前先问自己：能不能用盖牌区 / 指示物 / 基础效果 / 独有效果 / 场卡表达。
7. 每个角色都要有 `tests/cases/NN_角色拼音.gd`；本轮按要求**只做代码检查，不跑全量自检**。

### 2.1 F1 场卡的数据形状

```gdscript
{
  "id": String,        # 唯一键，如 "异端裁决所" / "末日预言" / "绝界"
  "owner": int,        # 拥有者（-1＝无主）
  "attached": int,     # 挂在谁面前（-1＝不挂人；绝界用）
  "counter": int,      # 主计数（裁决所=治疗点；末日预言=预言堆张数）
  "counter_max": int,  # 计数上限（末日预言 6）
  "state": int,        # 0/1/2 语义由各角色定义（末日预言：0=正面 / 1=天雷劫火 / 2=地裂波涛）
  "pile": Array[int],  # 隐藏牌堆（预言）；只把张数下发
  "public_cards": Array[int], # 公开牌面（如需要）
}
```
- 引擎原语：`加场卡(数据)` / `取场卡(id)` / `移除场卡(id)` / `场卡加计数(id, n)`。
- 快照：`field_cards`（不含 `pile` 内容，只 `pile_count`）。
- 客户端：`Data.场卡表`，面板状态区按 owner/attached 显示图标 + 「名字 计数/上限」；
  悬停说明写规则原文摘要。

### 2.2 F9 特殊卡（魔刃 / 异刃）

- 卡表新增两行：`special` 类型、`none` 系别、命格 `血`、资源名 `card/moRen` / `card/yiRen`。
- 两张卡**不进牌库**；由 7901【御刃】按“未在场”从卡堆/虚空加入手牌（引擎 `加特殊卡到手牌`）。
- 视为攻击牌：使用/打出/弃置时由角色选「火/水」（魔刃）或「雷/风」（异刃）；选择结果写进 `Action.args`，
  引擎按“视为系别”处理（复用 `技能视为系别` 的思路，但这里是**牌**不是技能 —— 见 F9 实现处的注释）。
- 【渗蚀】：使用、打出或弃置该牌时，噬神者对该牌的使用者 3 点法术伤害并移除；因技能放置到角色旁时对该角色 1 点并移除。

口径：
- 【魔刃】【异刃】“在场”＝在任意玩家手牌里；“未在场”＝既不在任何手牌也不在弃牌堆/盖牌区。
- 卡表「元素」支持或关系：`fire or water` / `thunder or wind`。`GCard` 解析成 `可选元素`，
  当前系别默认取第一个；所有通用系别逻辑（同系/异系、攻击牌白名单、弃牌费用等）都读当前 `element`。
- 系别切换发生在**手牌里**：鼠标指向手牌，卡牌**右上角**出现无底色的火/水（雷/风）小按钮；
  当前那颗置灰，另一颗点一下就把当前系别切过去。切换不消耗行动，任何时候都能切

- 切换是乐观更新：客户端先改卡面，再发 `Msg.CardElement` 给服务端；服务端改 `GCard` 当前系别、
  清 `_规则攻击牌缓存`，回一条带刷新后 `commands` 的 `CardElement`，客户端**原地**更新技能栏
  （不发 ErrorInput、不重建、不回滚，所以不会闪一下）。
- 两张牌现在就是**普通攻击牌**：当前 `element` 直接参与 `v_attack` / 应战 / 额外行动元素限制；
  不再有 7912 / 7913 攻击入口技能。`p_attack_card` 只负责记下本次用的实例，
  供【侵刻】/【噬灭】/【殇灭】判断。
- 渗蚀伤害的来源是噬神者，承伤者是「这张牌的使用者 / 被放到的角色」，不能写成固定「对你」；
  触发后通过 `ctx.removed` 把牌移出本次弃牌流程（不进弃牌堆），命中时由【侵刻】把同一实例交给目标。
- 三个被动【魔刃】7909 /【异刃】7910 /【渗蚀】7911 在技能表里各自成行，只承担角色说明；
  不要把三者合并回一条（踩过：三段【被动】挤在同一行，角色说明里显示不出来）。
- 【御刃】的选项走 `available_skills` 的 `arg_choices`（客户端格式是 `text / args`），
  和魔弓【魔眼】一样点技能直接进二级栏：可「返回」、点「确定」才提交，不再走服务端二次询问。
  选项带 `技能组`（魔刃：`[7909, 7911]`；异刃：`[7910, 7911]`），客户端悬停时把对应的
  被动与共用的【渗蚀】一起显示。踩过：旧实现把 `[1, 2]` 裸数字当 options 传给服务端询问，
  客户端既拿不到选项、点了也没有后续效果。

## 4. 关键口径与遗留

1. **星坠女巫的【律法】是标记不是牌**：本工程没有“律法牌”，实现成玩家状态 `laws`（1~3 个枚举），
   快照下发后在面板状态区显示名字。若后续设计表补“律法牌”，再迁移。
2. **结界/卢恩/妖力共用盖牌区**：三者的“面朝上/下”用 `cover_face_up` 区分；一个角色同时有多种旁置时，
   按 `tag` 字段区分（`cover_tag`），避免星坠女巫同时有卢恩和别的角色给的东西时串味。
3. **F9 的落点**：【魔刃】【异刃】的卡表元素写成 `fire or water` / `thunder or wind`，
   当前系别在手里切换；这两张牌**本身就是普通攻击牌**，按当前系别直接打出，
   不再有攻击技能入口。打出/弃置时【渗蚀】把牌移出游戏（不进弃牌堆）；
   命中时由【侵刻】把同一实例改交给攻击目标。命格按卡表血命格。
4. **场卡只有一个实例**（裁决所/末日预言/绝界），引擎按 id 唯一；重复放置走“转移到新位置”。
4. **魔刃/异刃“在场”判定**：在任意玩家手牌 = 在场；在弃牌堆/牌堆 = 不在场（可由【御刃】取回）。
5. **【黄金律】（4005）按简化口径**：群星启示后手牌 < 2 时只做了「摸 1 张」，
   「把 1 张手牌与 1 个【卢恩】交换」还没做（需要在群星启示收尾加一次二选一询问）。
6. **【贪婪】（9506）按简化口径**：翻面成【天雷劫火】/【地裂波涛】时只按「选一项」结算，
   还没有做「同时发动两项、顺序自定」的改写（需要在翻面流程里加一层排序询问）。
7. **未做**（本轮不做，记在这里）：重连时场卡/旁置区的补齐（快照已有，重连按快照重建）；
   角色立绘（39/40/43/79/82/84/95 的 L/S 图缺失，属美术任务）；词缀图标（新关键字的图标）。
