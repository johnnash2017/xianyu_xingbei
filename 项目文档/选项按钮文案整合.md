## 1. 背景：之前乱在哪

动手前用一次性脚本盘过一遍（盘点脚本是临时的，跑完已删；口径：`label` / `text` 字段去重计数）：

| 现象 | 数据 |
| --- | --- |
| 脚本里 `label` / `text` 选项字段 | **209 条，分布 46 个文件** |
| 其中写死的静态文案（含 `%d`/`%s` 模板） | **114 条** |
| 其余是表达式（变量、函数调用、条件拼接） | 95 条 |

具体三类乱象：

1. **同一条按钮写两遍**：`"text"` 给 `available_skills` 的 `arg_choices`、`"label"` 给
   `ask_skill` 下发的 `notes`，两处各写一份同样的字面量（`role_daduoshaonv.gd` 的注释
   自己就写着「ask_skill 走 label、arg_choices 走 text」）。
2. **按钮文案寄生在提示列**：P4 迁移提示时，有些按钮的 label 被顺手改成了
   `提示原文(技能, 序号)` / `提示(技能, 序号)`，按钮文字实际存在「提示」列里，
   改按钮要去动提示文案。
3. **文本表里塞技能专属句**：`提示_冰冻_指定角色`、`提示_阴阳转换_*` 这类明显属于某个技能的句子，
   因为「两个技能共用 / 两个调用点」被放进了文本表。

## 2. 目标与设计

### 2.1 数据：技能表加 8 列

- 列名：`按钮`、`按钮2` … `按钮8`（与提示列同结构，共 8 列）；
- 类型行：`按钮` = `list(string)#distributed`，`按钮2~8` = `list(string)#distributed(按钮)`；
- **导表器不用改**：`#distributed` 是通用机制（提示列就是这么用的），
  转表时把「主体列 + 各分列」按从左到右并成一个数组；
- 与提示列相同的空格规则：中间留空会导出 `[""]` 占位，后面的条目不会左移；
- 与提示列**不同**的一点：**按钮没有「第 0 条自动当默认文案」的语义**，
  序号只是地址，填第几条、取第几条都行（提示列的 `提示[0]` 会被 `询问()` 当默认提示用）。

### 2.2 代码：三个访问器

| 接口 | 位置 | 口径 |
| --- | --- | --- |
| `GConst.技能按钮列表(技能)` | `scripts/core/const.gd` | 取整个按钮数组 |
| `GConst.按钮原文(技能, 序号, 额外)` | 同上 | **不加**数字前后空格；`%d`/`%s` 由调用方格式化，`{键}` 按 `额外` 填 |
| `GConst.按钮文本(技能, 序号, 额外)` | 同上 | **加**数字前后空格（与 `提示文本` 同口径），只给「原来用 `提示()` 取按钮」的地方保留渲染 |
| `BattleRole.按钮(...)` | `scripts/battle/battle_role.gd` | 角色脚本里的便捷包装 |

「原样」与「加空格」两个接口是**刻意并存**的：同一个数字在提示和按钮里可能要求不同间距，
迁移时按下表选，保证迁移前后**逐字一致**。

### 2.3 校验：51 号用例扩展

`tests/cases/51_textIds.gd` 新增 `_校验按钮原文`：

- 扫角色 / helper 脚本里的 `按钮原文(技能, 序号)` / `按钮文本(技能, 序号)`；
- 技能号支持数字、本文件 `const`、`GConst.const`；动态写法（函数调用等）跳过；
- 技能行 / 序号不存在 → 报错；**取到空串也报错**（按钮会变成空白）；
- 顺带修掉旧代码里两处「计数器写在 `continue` 之后」的永不可达语句。

### 2.4 约定

写进《技能维护约定》「提示列排布约定」小节：

- 技能专属按钮文字 → 技能表按钮列；
- **一条按钮要被两个技能共用** → 构造函数带「技能号」参数，两行各配一份，用哪个取哪个；
- **由数据拼出来的文案不进表**（系名、卡名、数字档位这类拼接结果）；
- 文本表只留「没有唯一技能归属」的客户端通用句。

## 3. 迁移口径（按原来的写法分三类）

| 原来怎么写 | 改成什么 | 注意 |
| --- | --- | --- |
| 写死的字面量 `"label": "移除 2 张牌"` | `GConst.按钮原文(技能, 序号)` | 文本原样搬进表 |
| 读提示列：`提示原文(技能, n)` | 文本搬进按钮列 → `按钮原文(技能, 新序号)` | 原提示条目**先保留**（可能还被 `询问` 的序号用着，清理另说） |
| 读提示列：`提示(技能, n)` / `提示文本(...)` | 文本搬进按钮列 → `按钮文本(技能, 新序号)` | 这两个会按数字规则补空格，必须用「加空格版」才对得上原渲染 |
| 带占位符：`"摸 %d 张"` / `"摸{n}张"` | 模板原样进表 | `%d`/`%s` 留在代码里格式化；`{n}`/`{n2}`/`{花费}` 用 `额外` 字典填 |
| 两个技能共用一个构造函数 | 函数加参数 `技能号`，两行各写一份 | 例：3301/3306 的阴阳转换三档、8806/8808 的士气方向 |
| 技能号运行时才定 / 内部子询问号 | 读**母技能**那一行 | 内部子号会被 `技能行()` 折到母技能行（同「冰冻治疗」口径） |
| 系名 / 卡名拼出来的 | **留在代码** | 这是拼接结果，进表反而多一层间接 |

### 5.1 明确不进表的（按约定保留在代码里）

- 治疗抵挡：「不抵挡 / 挡 N 点」—— 所有伤害事件共用的基础规则 UI，不归某个技能行；
- 购买 / 合成 / 提炼菜单；
- 星石组合文案（`_提炼选项文案`、`_选特殊行动` 的组合句）—— 由当前战绩区数量拼出来；
- 基础效果牌面 `%s【%s】%s` —— 由基础效果类型与卡名拼出来。

### 5.2 逐字一致的证据

- 迁移用的是「把同一行原文复制进按钮列」的方式，取文接口按原口径二选一（加/不加空格）；

## 6. 踩过的坑（都写进了提交说明）

| 坑 | 现象 | 结论 |
| --- | --- | --- |
| 自动替换多写 `)` | 54 处双右括号 → 脚本解析失败、自检卡死 | 只替换「前缀 + 参数」，右括号留给原文；改完 `--check-only` 逐个验 |
| 同名常量不同值 | 冒险家 `TOU_TIAN_HUAN_RI`=1203、冒险家Trick=8903，解析用全局表会挂到 1203 | 解析优先本文件 `const`；51 号用例会直接报「技能 X 只有 0 条按钮文案」 |
| 写表脚本用过期快照 | 407 已有按钮被当空数组覆盖，只剩新加那条 | 写表前先重新导出当前表；51 号用例发现后按完整两条重写 |
| 挂错技能行 | 苍白之月的选项一度写进 3503（魅杜莎之眼） | 核对构造函数调用方（`_cang_bai_choices` 属于 3507）再写表 |
| 共用选项硬编码 | 3301/3306、8806/8808 共用一组按钮 | 构造函数带 `技能号`，两行各配一份，不做文本表 |
| 51 断言过时 | 角色侧已无 `文本(id)` 引用，旧断言「至少一条」失败 | 去掉「至少一条」，保留「有引用就必须存在」 |

## 7. 后续（可做但本次没做）

1. **提示列清死条目**：有些条目原本只被当按钮用（如 407 的第 2 条提示），现在可能没人引用了。
   清理前要同时扫三处引用：`询问(...)` 的「序号」参数、`提示原文/提示文本` 调用、
   `技能指示器` 的「提示序号」配置——只扫其中一处会误删。
2. **客户端基础菜单要不要统一**：治疗抵挡 / 购买 / 合成 / 提炼 / 星石组合目前按约定留在代码里；
   如果要进表，需要先定「挂到哪一行」的规则（它们不属于任何技能）。
3. **收口后的新技能**：按下节步骤操作即可；加按钮时优先**往后追加**，
   中间插队会让后面的序号整体挪位（各调用点都要跟着改）。

## 8. 新增 / 修改按钮文案的操作步骤

1. 打开 `Table/Design/设计表.xlsx` 的「技能表.csv」，按技能找到行；
2. 在 `按钮` … `按钮8` 里填文字（**第一列不必是「默认按钮」**，序号只是地址；
   带数字就写 `%d`，要填参数写 `{n}` / `{花费}` 这类占位符）；
3. 代码里取：`GConst.按钮原文(技能号, 序号)`（要数字空格时用 `按钮文本`）；
   选项字典的 `"label"`（`ask_skill` → 客户端按钮）和 `"text"`（`arg_choices`）**两处都填**；
4. 按 Ctrl+Shift+T（或 `godot --headless --path . --script res://tests/tools/export_tables.gd`）导表；
5. 跑 `tests/runSelfCheck.ps1`：51 号会校验技能号/序号存在且非空；
6. 两个技能共用一条按钮时，不要进文本表——构造函数加 `技能号` 参数，两行各写一份。
