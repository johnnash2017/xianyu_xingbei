# 攻击伤害预览（头像上的数字）

> 一句话：**头像上“这一击会打多少”的数字，只在服务端算一处；客户端只负责画。**
> 少数“要等玩家选完牌/选项才知道”的技能，用**配置表**描述差异，不再一个技能写一个函数。

## 1. 为什么收口

以前同一个伤害在多个地方各算一遍：

- 服务端结算一份（`harm.point`）；
- 客户端每个技能一个头像提示函数，自己再按「技能号 → 加伤表」加一次；
- 角色被动（狂化）、荒神之力、百式的 +2 又各在几个函数里补。

结果是「显示 ≠ 实际」的一类 bug 反复出现：格斗【蓄力一击】显示 2、实际 4；气绝崩击在结界/荒神/百式组合下算错；【欺诈】没有伤害提示。**每修一个都要把“客户端那份算法”再对一遍服务端。**

收口后：服务端给数 → 协议下发 → 客户端两个渲染器画。新增技能只在表里加一行。

## 2. 数据流

```text
服务端                     协议（CmdReq）                    客户端
────────────────────────────────────────────────────────────────────────────
攻击预览伤害(ctx)  ──▶  preview_base       ──┐
  = harm.point + 角色 p_attack_preview        │
                                              ├─▶ _攻击伤害头像提示()   （有询问）
发动后的数        ──▶  preview_damage       ──┤      · 两行「原值划掉 → 新值」
每个选项的数      ──▶  option_damages[i]    ──┘      · 多选项时按选中项取数

（无询问的攻击技能）
表 GConst.攻击技能伤害预览 ─────────────────────▶ _攻击技能伤害头像提示()
                                                  伤害 = 攻击基础 + 荒神(系别)
```

## 3. 协议字段

| 字段 | 位置 | 含义 |
| --- | --- | --- |
| `preview_base` | `CmdReq` | **不发动**这次技能时的伤害（已含荒神 / 狂化 / 百式这些自动加成） |
| `preview_damage` | `CmdReq` | 发动之后的伤害；不改变伤害时不下发（-1） |
| `preview_kind` | `CmdReq` | 伤害类型（攻击 / 法术 / 治疗），决定文案用词 |
| `preview_ids` / `dst_ids` | `CmdReq` | 画在谁的头像上 |
| `option_damages` | `CmdReq` | 与选项一一对应：选了这一项之后的伤害（0＝这项不改伤害） |
| `preview_rule` | `CmdReq` | 按「玩家当前选择」现算加伤的小规则（见 5.4）：`card`、`card:3`、`option`、常数，用 `+` 连接 |
| `damage` | `Option` | 同 `option_damages` 的新格式（见 5.2 的 `options` 消息） |

服务端生成入口只有一个：`BattleEngine.攻击预览伤害(ctx)`（角色侧包装 `BattleRole.攻击预览伤害(ctx)`）。

## 4. 服务端约定

### 4.1 `攻击预览伤害(ctx)`

```gdscript
func 攻击预览伤害(ctx: Dictionary) -> int:
	return int(ctx.get("harm", {}).get("point", 0)) + _预告加伤(int(ctx.get("src", -1)), ctx)
```

- 应战提示也走它（`_应战提示伤害` 只是把 harm 塞进 ctx 再调它）。
- 所有会改这次攻击伤害的询问，都拿它当 `预览基准`。

### 4.2 `p_attack_preview` 的口径

**只返回「还没加进 `harm.point`、但命中时一定会加」的那部分。**

| 情况 | 写法 |
| --- | --- |
| 荒神之力 | 在 `p_before_attack` 已经加进 `harm.point` → **不要**再返回，否则预览会重复算 |
| 狂化（狂战士） | 命中时才加 → 返回 `1 + (手牌 > 3 ? 1 : 0)`，**基数 +1 也由它出**（客户端不再补） |
| 暗影之力 / 暗之解放 / 恶魔之魂 等 | 同上，命中才加 → 全部由它返回 |
| 百式 +2（格斗） | 不放进 `p_attack_preview`：蓄力会取消百式，所以单独用 `_百式加成(ctx)` 算“保持百式”的基准 |

### 4.3 共享询问（格斗蓄力/气绝）

同一个询问里两个选项，伤害不一样 → 用 `option_damages` 每项各带一份：

```gdscript
var 基准 := 攻击预览伤害(ctx) + _百式加成(ctx)   # 不发动 = 保持百式
选项 = [
	{"value": 蓄力, "damage": 攻击预览伤害(ctx) + 1},  # 蓄力打断百式
	{"value": 气绝, "damage": 基准},                   # 气绝不改伤害
]
```

### 4.4 按系别加伤的被动（荒神）

荒神之力在 `p_before_attack` 已经并进 `harm.point`，所以**正常攻击**的预览不用再算它。
但有些攻击**还没建立 harm**（如魔弓【多重射击】的暗系虚拟攻击），这时用：

- `BattleRole.p_attack_element_bonus(元素)`：角色回答“这个系别的攻击你会加几点”（结界师 = 1）；
- `BattleEngine.攻击元素加伤(元素)`：问一遍所有角色后求和。

> 只给“还没建立 harm”的场合用。已经进 `harm.point` 的攻击再调它会重复加。

## 5. 客户端约定

### 5.1 两个渲染器

| 渲染器 | 适用 | 逻辑 |
| --- | --- | --- |
| `_攻击伤害头像提示()` | **有询问**（mode 3），排在提示链第一条 | 新伤害 = 选中选项的 `伤害` ＞ `preview_damage` ＞ 基准+规则；与基准不同就画两行 |
| `_攻击技能伤害头像提示()` | **无询问**的攻击技能（mode 4） | 查 `GConst.攻击技能伤害预览`，伤害 = 攻击基础 + `_荒神之力加伤(系别)` |

排除项（`_攻击伤害头像提示` 里写死）：

- 4302 神威 / 4303 圣裁：服务端已给数，但提示还带“自身吃 1 点法术伤害 / 选 X”这类额外内容，走它们自己的函数；
- 3301 式神咒束 / 4205 阴阳转换：`preview_base` 是**攻击牌 id**，不是伤害；
- `preview_kind == 预览类型_治疗`：治疗预览不走伤害渲染。

### 5.2 选项伤害的两种来源

- 旧：13 个平行数组（`option_damages`）；
- 新：`options` 里每个 `Option` 一条，带 `damage` 字段。

客户端 `_选项源_嵌套()` / `_选项源_平行数组()` 两条路径都归一化成每个选项的 `"伤害"`，`_规整选项` 会把未知键原样带进内部结构。

**行动结束响应（聚合器）**也支持：选项里带 `preview_base` 时引擎把它当询问的 `预览基准` 下发（如魔弓【多重射击】的虚拟暗系攻击），选项自己的 `damage` 照常下发。

### 5.3 `preview_rule`：随选择变化的加伤

有些技能加多少要看玩家**选了几张 / 选了哪些牌 / 选了哪一档选项**，服务端发询问时还不知道。
这时服务端只给**规则**，客户端按当前选择现算：

```text
规则串 = 若干项用 "," 连接
  card      每张已选牌 +1
  card:3    每张已选牌里系别 = 3（火）的 +1
  option    加「选中选项的值」
  eff:3     「这次攻击算的系别」= 3（火）时 +1（子弹/视为系别这类）
  -2 / 3    纯数字＝常数
```

选牌还没选够（`_need_cards`）时：**带常数的规则**（如战纹碎击 `option,card,-2`）按 0 算，避免负数；
只按选项/张数/系别算的规则（暗月斩 `card`、禁断之力 `card:3`、索拉 `eff:3`）选几张就按几张预览。

例：

| 技能 | 规则 | 含义 |
| --- | --- | --- |
| 月女【暗月斩】 | `card` | 每移除 1 张【暗月】+1 |
| 勇者【禁断之力】 | `card:3` | 每弃 1 张火系手牌 +1（同时反噬同点数） |
| 英灵人形【战纹碎击】 | `option,card,-2` | 弃 2 张同系牌 +1，额外翻转 Y 个再 +Y（选项值 = Y+1） |
| 游击士【元素射击*索拉】 | `eff:3` | 子弹（或“视为系别”）是火系时 +1 |

两条求值约定：

- `option` 还没选时按**第一项可用选项**的值算（战纹碎击默认「不额外翻转」，与迁移前一致）；
- 规则里带常数（`-2`）的，要选满 `_skill_need_card` 张牌才加，避免还没选完就出现负数。

客户端只有 `_预览规则加成()` 一个求值器（[battle_mobile.gd](../scripts/ui/battle_mobile.gd)），不再按技能号分支。

### 5.4 自己头像上的附带文案（`攻击伤害自身附带`）

| 值 | 含义 |
| --- | --- |
| 字符串 | 原样写在自己头像上（如杀戮盛宴 `"4 法术伤害"`） |
| `{"文案": "%d 法术伤害"}` | `%d` 用「本次加伤的点数」填（如禁断之力反噬） |

### 5.5 目标派生伤害表（`攻击技能派生伤害`）

无询问技能的伤害若取决于**当前点选了哪些目标**，用这张表 + 一个求值器 `_派生伤害(技能号)`：

| 规则 | 含义 |
| --- | --- |
| `tgt_heal` | 每个“有治疗”的目标 +1（圣弓【圣光爆裂】） |
| `morale` | 任一目标队伍士气高于我方时 +`落后`值（圣弓【天火断空】） |

配置项：`基础`（默认攻击基础 2）、`规则`、`落后`。技能自己的提示只负责排版，不再自己数目标。

配置项：`基础`（默认攻击基础 2）、`规则`、`落后`。技能自己的提示只负责排版，不再自己数目标。

### 5.6 配置表（`GConst`）

| 表 | 用途 | 例 |
| --- | --- | --- |
| `攻击技能伤害预览` | 无询问攻击技能的**系别来源**（0＝已选牌 / 1＝二级栏选项里的虚牌） | 圣屑飓暴 0、欺诈 1 |
| `攻击伤害用词` | 历史文案不是“攻击伤害”的，按原样保留 | 杀戮盛宴 → “物理伤害” |
| `攻击伤害自身附带` | 目标之外，自己头像上还要写一句 | 杀戮盛宴 → “4 法术伤害” |

`_荒神之力加伤(元素)` 是客户端**唯一**保留的伤害计算：荒神取决于“这次攻击的系别”，而系别要到玩家选完牌/选项才知道，服务端发询问那一刻拿不到。

## 6. 新增/迁移一个技能的步骤

1. 服务端：在改伤的询问里算 `基准 = 攻击预览伤害(ctx)`，按需带 `preview_damage` 或每个选项的 `damage`；
2. 删掉客户端那个 `_XXX头像提示()` 和它在提示链里的调用；
3. 如果文案不是“攻击伤害”→ `GConst.攻击伤害用词` 加一行；
4. 如果自己头像上还有附带文案 → `GConst.攻击伤害自身附带` 加一行；
5. 如果是无询问的攻击技能 → `GConst.攻击技能伤害预览` 加一行（配系别来源）；
6. 静态核对：`grep` 确认旧函数没人引用；如果要删函数，先跑 `tests/查死代码.ps1`（自检用例里可能直接调它）。

## 8. 踩过的坑

1. **荒神不能塞进 `p_attack_preview`**：它在 `p_before_attack` 已进 `harm.point`，再返回就重复。
2. **格斗的共享询问**：`preview_damage` 只能表达一个数，两个选项伤害不同必须用 `option_damages`。
3. **格斗蓄力会打断百式**：基准要按“保持百式”算，否则会显示成 `2 划掉 → 4`（实际是 `4 划掉 → 3`）。
4. **杀戮盛宴的文案**：历史上写“物理伤害”，迁移时用 `攻击伤害用词` 保住，不要顺手统一成“攻击伤害”。
5. **式神咒束 / 阴阳转换**：`preview_base` 是攻击牌 id，任何按“伤害”解释的通用渲染都要把它们排除。
6. **应战提示**：客户端以前在 `args[5]` 之外又加了一次狂化 +1，服务端折叠后必须删掉那两处（否则双算）。
7. **旧实现已清理**：`_攻击加成头像提示`、`_攻击提示加伤`、`_元素射击/地枪/威力赐福/暗月斩头像提示` 和 `攻击提示加成` / `攻击提示角色加成` / `攻击提示_命中后结算` 三张表都已删除；自检用例（`4_battleInteraction` / `12_yuenvIndicators` / `45_newroles`）改成直接调通用渲染器，构造 `preview_damage` / `preview_rule` / `option_damages`。
