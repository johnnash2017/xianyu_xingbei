## 0. 结论先行

1. **现状确实不统一**：仓库里同时存在 5 类写法（见第 1 节），同一个需求（「回退到上一步」）有 3 种表达方式
   （表里配键 / 客户端硬编码 / 角色自己重问）。
2. **不统一的部分只有一处是真乱**：**多步之间的「回退」**。其余差异（客户端本地 vs 服务端分段）是本质差异，
   不该合并。
3. **建议**：抽一层薄薄的「多步询问」框架（服务端段 + 本地段 + 统一回退 + 统一超时/重连），
   底层仍用现有 `ask_skill`；分 4 个阶段迁移，**存量技能不强制重写**。

## 1. 现有写法盘点

### 1.1 五类写法

| 类别 | 做法 | 数量（2026-11-10 扫描） | 代表 |
| --- | --- | --- | --- |
| **A. 客户端本地二级栏 `arg_choices`** | 技能按钮上一次下发全部选项，客户端本地切换；「确定」一次提交；「返回」＝不发动 | **31** 个角色脚本用到 | 魔弓【魔眼】2605、充能 2604、雷光散射 2602、异教徒【放逐】9505 |
| **B. 服务端分段询问 + 段号状态机** | 角色自己记 `_xxx阶段`，钩子重入时按段号推进，每段一次 `询问()` | **119** 个段号变量，分布在 **50** 个角色脚本；角色里共 **235** 处 `询问(` | 军神威光 2504、魑魅魍魉 8404（第二段复用 8401/8402 的技能号）、狂戾之心 8303、神智污染 8305、扭曲之爱 8306 |
| **C. 「回退到上一段」** | 空应答＝退回上一段重问 | **已统一**：指示器键 0 条、服务端分段全走询问参数 `可返回`；客户端只剩 **6** 个「本地分层」函数（见 1.3，不属于服务端分段） | 魑魅魍魉 8404、军神威光 2504、魔纹融合 2701（这三个已迁完）；苍白之月 3507、圣光爆裂 3704、自动填充 3707 属本地分层 |
| **D. 客户端纯本地分层** | 不经过服务端询问，纯 UI 分层 | `_本地二层`（3 个技能共用，`eeb0888`）、`_本地选项阶段`(0~6)、`_提炼阶段` | 苍白之月/圣光爆裂/自动填充的第二层（已统一）、购买/合成/提炼、恩典神授代价、冒险家天堂分配 |
| **E. 引擎侧机制**（不是角色写法，是地基） | 状态栈、`保留倒计时`、`_挂起回复`、行动聚合器待决、重连补发 | — | `battle_engine.gd` 的 `SAskCross` / `SkillRun` / `S行动聚合器` |

补充：B 类内部还有两种代码组织风格，**行为等价、只是写法不同**：

- **B1**：同一个函数里 `if _阶段 == 0: ... if _阶段 == 1: ...`（多数角色）；
- **B2**：每段一个函数，入口按段号 `match` 分派（军神威光、放逐、扭曲之爱）。

### 1.2 一个真实的杂乱样本：扭曲之爱的三次返工

| 版本 | 写法 | 问题 |
| --- | --- | --- |
| 初版 | 一次询问 7 个平铺选项（形态 × 弃/摸 × 戾气） | 十几个选项糊成一片，需求方要求拆段 |
| 第二版 | 第一段 `arg_choices`（本地）+ 后两段服务端询问 | 本地段与服务端段混用：返回时服务端要重问第一段，两条通道不一致；闪屏、选项被抹掉 |
| 第三版（当前） | 三段全部服务端询问（B2）+ `可返回` 参数 | 结构统一了，但角色里仍有 3 个段函数 + 段号 + 「已完成」态 |

也就是说：**同一个技能，三次实现三种结构**——这正是「缺乏统一」最直接的证据。

### 1.3 客户端里跟多步相关的技能专属代码

`battle_mobile.gd` 里按技能号写的多步专用函数（8 个）：

| 客户端函数 | 对应技能 | 现在怎么回退 |
| --- | --- | --- |
| ~~`_军神威光返回()`~~ | 军神威光 2504 | **已删除**（改用询问参数 `可返回`，`3b73c9c`） |
| ~~`_魔纹本体返回()`~~ | 魔纹融合 2701 | **已删除**（同上） |
| `_进入苍白月第二段()` / `_返回苍白月第一层()` | 苍白之月 3507 | 本地 `_苍白第二步` 标志 |
| `_进入圣光爆裂第二层()` / `_返回圣光爆裂第一层()` | 圣光爆裂 3704 | 本地 `_圣光爆裂第二步` 标志 |
| `_进入自动填充第二层()` / `_返回自动填充第一层()` | 自动填充 3707 | 本地 `_自动填充第二步` 标志 |

三个本地分层技能的第二层已收敛成通用机制（`eeb0888`），但它们仍各有一个「点选项触发进入第二层」的判断。

另有 **93** 处客户端 `GConst.技能_*` 判断（`_选项选中立刻处理`、`_确定_*`、提示文案、播报等），
其中一部分就是「这个技能点选项要不要立刻提交」「返回退到哪一层」这类**流程性**特判。

### 1.4 为什么会有这么多写法（历史原因，不是谁写歪了）

1. **A 与 B 的差别是本质的**：选系别、选摸几张这类不需要服务端校验的，做成客户端本地（A）最快；
   选牌是否合法、随机数、状态变化必须服务端算（B）。
2. **`arg_choices` 只能支撑一段**：需要「选完这一段再选下一段」时，只能回落到服务端分段询问（B）。
3. **「回退」当初没有通用说法**：每个技能第一次需要回退时，就在客户端加一个函数 / 在表里加一条键，
   于是 C 变成「一个技能一套」。
4. **引擎的 `step` 不能跨询问**：钩子轮次开始会清零 `step`，所以分段只能靠角色自己的变量 → 119 个段号变量。
   这是规则决定的，不是设计冗余。

## 2. 需求清单（从现有技能倒推）

把现存「一个函数问多次」的多段询问（清扫口径见 5.5：共 30 个函数）的诉求归纳成 12 条，框架必须能容纳：

| # | 需求 | 现有例子 | 现在的实现方式 |
| --- | --- | --- | --- |
| R1 | 顺序多段，每段只问一件事 | 扭曲之爱（形态→弃/摸→戾气） | 段号 + 逐段询问 |
| R2 | 段间有服务端副作用（扣费、弃牌、摸牌、形态变化） | 扭曲之爱扣宝石、狂戾之心弃牌 | 角色自己按顺序做 |
| R3 | 能退回上一段，且**已发生的副作用不能白吃** | 扭曲之爱（弃牌推迟到结算） | 角色自己把副作用推迟 |
| R4 | 整条链共用一个倒计时 / 或每段独立计时 | 军神威光（`保留倒计时`） | 询问参数 |
| R5 | 超时默认值（放弃 / 默认选项 / 最保守结算） | 军神威光超时＝选项① | 角色在空应答分支里判 `is_timeout` |
| R6 | 每段各自的选牌白名单、张数、来源（手牌/盖牌）、系别/命格限制 | 狂戾之心（弃 1 + 选目标同段） | `ask_skill` 参数 |
| R7 | 同一段内「选牌 + 选目标」合并问 | 狂戾之心、军神威光第二段 | `need_card` + `need_target` |
| R8 | 选项决定后续需牌/需目标数 | 魔眼、放逐 | 选项自带 `need_card`/`need_target` |
| R9 | 同一个技能里既有服务端段又有纯本地段 | 圣光爆裂（选群体 → 本地选 X） | 客户端本地分层（D） |
| R10 | 断线重连后能继续当前段 | 所有分段技能 | 引擎重发「正等他的那份询问」 |
| R11 | 非法提交要能重问当前段而不是整条链作废 | 扭曲之爱（弃牌张数不对） | 角色 `报错` + 结束 / 或重问 |
| R12 | 预览数值（本段会打多少伤害 / 加多少治疗） | 神智污染、撕裂、军神威光 | `预览基准` / `预览类型` / `预览目标` |

## 3. 统一框架设计（已实现）

### 3.1 分层

```text
┌──────────────────────────────────────────────┐
│ 角色脚本：只声明「一条多步询问」+ 结算回调        │  ← 新增的薄封装
├──────────────────────────────────────────────┤
│ BattleRole.多步询问（框架层）                    │
│   · 段进度（不再每个技能一个 _xxx阶段 变量）      │
│   · 回退（空应答 → 上一段重问）                  │
│   · 超时（链级 deadline + 每段默认值）           │
│   · 副作用（统一在结算回调里做，回退不撤账）      │
├──────────────────────────────────────────────┤
│ ask_skill / 询问（现有底层，不动）                │
├──────────────────────────────────────────────┤
│ 客户端：按「段类型 + 选项 + 可返回」渲染，        │
│         不再按技能号写返回分支                   │
└──────────────────────────────────────────────┘
```

### 3.2 角色侧 API（已实现；终版签名见 `battle_role.gd`）

```gdscript
## 声明一条多步询问。返回 WAIT＝正在问；链走完后调用「结算」，
## 结算的返回值原样交给引擎（SUCCESS / URGENT）。
func 多步询问(链号: int, 段表: Array, 结算: Callable, 收尾: Callable = Callable()) -> int
func 多步询问重置(链号: int) -> void       # 新一次发动 / 回合开始时清残留
func 多步询问进行中(链号: int) -> bool     # 钩子类技能用它挡「别的同类事件插进来」
```

- **`链号`**：一般用技能号；同一函数里跑多件技能时**每件一条链**（噬神者/异教徒就是按技能号分开的）。
- **`收尾`**：结算里压了状态（返回 URGENT/WAIT）时，引擎重入会先跑它；它自己还能再压状态并返回 URGENT，
  会一直被重入到返回 SUCCESS（荒神祭祀的「移除结界 → 横置」）。

**段规格（Dictionary，键都可省）**

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `选项` | Array / Callable | 选项列表（字段同 `ask_skill`）；用 Callable(答案) 可**按前面答案现算** |
| `需牌` / `需目标` | int / Callable | 这一段要选几张牌 / 几名角色（0＝不选） |
| `来源` | int | `GConst.CardSource`，默认手牌 |
| `牌白` / `目标白` | Array / Callable | 白名单（牌白名单按**牌面**） |
| `牌规则` / `牌上限` | String / int / Callable | 同 `ask_skill` 的 `card_rule` / `card_max`（如 `"same"` / `"diff"`；`牌上限` 可给 Callable，`牌规则` 只认字符串） |
| `可返回` | bool | 这一段空应答＝退回上一段重问（客户端据此摆「返回」） |
| `可取消` | bool | 这一段空应答＝整条链取消（默认 true）；false＝空应答按「没选」继续走 校验 / 答完 / 结算（旧实现里强制段收到空回复都是自己补弃 / 补取） |
| `取消` | Callable()→int | 整条链取消（含超时）时的回调；**它自己可以压状态并返回 URGENT/WAIT** |
| `跳过` | Callable(答案)→bool | **条件段**：返回 true 就跳过这一段不问（每次重入都会重新判） |
| `空继续` | bool | 这一段收到空应答（玩家点取消）时不取消整条链，按空答案继续走 答完 / 结算（如魑魅魍魉的「要不要展示」）；超时还要另配 `超时默认` |
| `问前` | Callable(答案) | 真正发问前跑一次（技能名播报 / 展示这类前置），重问本段也会再跑 |
| **`重复`** | Callable(回, 答案)→bool | **循环段**：为真时留在本段重问、答案就地覆盖（「对每个目标各问一次」） |
| `答完` | Callable(回, 答案)→int | 这一段答完**立刻结算**（可压状态并返回 URGENT/WAIT）；段号已推进，重入从下一段继续 |
| `超时` | Callable()→int | 超时直接调它收尾（优先于 `超时默认`） |
| `超时默认` | Variant | 超时把这一段当作这个答案，照常走 答完 / 重复 / 结算（`[]`＝空答案交给「答完」兜底）；可取消的段都没有才按「不发动」取消整条链 |
| `校验` | Callable(回)→bool | 段内合法性；不合法回一条错误日志（`Gossip` Error）＋一条 `ErrorInput` 给被问的人，然后重问本段 |
| `校验失败回退` | bool | 校验不过时退回上一段（默认重问本段） |
| `校验失败文案` | String | 上面那条错误日志的文案（省略＝「操作无效，请重新选择」） |
| `问谁` | int / Callable | 这一段问哪名玩家（默认自己；「队友代答」「问目标弃哪张牌」用） |
| `技能号` | int / Callable | 这一段用哪颗技能号发问（默认＝链号；一条链里跨两颗技能时用） |
| `响应` | `{"type", "args"}` | 这一段改用**标准应答**发问（如 `RespondType.Discard` 让别人弃牌），不用技能询问 |
| `提示序号` / `询问文案` / `张数` / `收牌人` / `额外` / `默认选项` | — | 同 `ask_skill` 对应参数（`询问文案` / `张数` / `收牌人` 也支持 Callable(答案)：圣剑、魔法入门、异教徒按已答的答案现算张数与收牌人） |
| `预览基准` / `预览类型` / `预览目标` / `预览伤害` / `可圣光` / `高亮` / `超时目标` / `需盖牌` / `盖牌最多` / `手牌数` | — | 同 `ask_skill` 对应参数（`预览基准` / `预览目标` 也支持 Callable） |

**答案**：`结算` / `答完` 收到 `Array`（或单个答案项），每项
`{"args": Array, "cards": Array, "dsts": Array, "timeout": bool}`，**只装真正问过的段**，按答题顺序排列。
被 `跳过` 的段不占槽位 —— 所以 `答案[i]` 不等于「第 i 段」，写死下标的技能要确认那一段不会被跳过；
取「最后答的那一段」用 `答案[答案.size() - 1]`（圣炎祈愿就是这么取的）。
`timeout` 是引擎的**超时兜底回复**标记 —— 段里要按「伤害补敌人 / 治疗补友方」这类规则代打时靠它判断
（矜贵之女【魔法入门】就是这么做的）。

现成例子（扭曲之爱 8306，`00c0fe9`）：

```gdscript
func p_special_skill(_action: Dictionary) -> int:
	return 多步询问(NIU_QU_ZHI_AI, [
		{"选项": _扭曲形态选项()},
		{"选项": _扭曲弃摸选项(), "可返回": true},
		{"选项": _扭曲戾气选项(), "可返回": true},
	], _扭曲结算)


func _扭曲结算(答案: Array) -> int:
	# 只在这里做副作用：扣宝石、调戾气、落形态、弃牌 / 摸牌
	...
```

另两个形态（条件段 / 校验 / 超时回调）见 `role_nvwushen.gd` 的 `p_turn_begin`（军神威光）与
`role_yinglingrenxing.gd` 的 `p_timeline_2_miss`（魔纹融合）。

### 3.3 框架内部的规则（已实现）

| 事项 | 规则 |
| --- | --- |
| 段进度 | 存在角色对象的 `_多步链` 里：`{链号: {"段": int, "答案": Array}}`，角色不再手写段号变量 |
| 回退 | 客户端「返回」→ 空应答 → 退回上一段（丢弃那一段的答案）并重问；第一段空应答＝整条链取消 |
| 副作用 | 段内可以用 `答完` 先结算（跨段依赖时必需）；其余**一律放在结算回调**，回退天然不用撤账 |
| 循环段 | 段字段 `重复`：为真时留在本段重问、答案就地覆盖；**答完压了状态时会延后到重入后再判**（见 5.2 第 23 条） |
| 超时 | 超时优先 `超时` 回调，其次 `超时默认`（当作已经这样答了，照常走 答完 / 重复 / 结算，不跑段级校验）；可取消的段两者都没有＝按「不发动」取消整条链；**不可取消的段两者都没有＝按空答案继续走 答完 / 结算**（强制弃牌 / 取牌由角色兜底补完）；超时也会走 `取消` 回调 |
| 非法提交 | 有 `校验` 的段按 `校验失败回退` 决定「重问本段 / 退回上一段」，并回一条错误日志（`Gossip` Error）＋给被问的人发一条 `ErrorInput`（客户端提示「操作无效」，与迁移前角色自己发的口径一致） |
| 第二段起的倒计时 | 框架给第 2 段及以后自动带 `保留倒计时`，整条链共用一个截止时刻 |
| URGENT 重入 | 结算里压了状态并返回 URGENT 时，**`收尾` 回调**会在重入时先跑（可多次）；没有收尾的技能仍要自己挡（见 5.2 第 12 条） |
| 断线重连 | 进度在服务端内存，沿用现有「重发正等他的那份询问」机制 |
| 与 `arg_choices` 的关系 | `arg_choices` 仍是「客户端本地单步选择」，与服务端分段是两类需求，共存 |

### 5.2 问题与决定
1. **`while true` 的返回值**：框架主循环每个分支都是 `return` / `continue`，GDScript 仍报
   「Not all code paths return a value」→ 函数末尾补一个不可达的 `return SUCCESS`，只为过解析。
2. **超时策略（第一版写错，已改）**：初版是「空应答且这一段不可取消 → 重问这一段」，
   但掉线 / 挂机玩家的默认回复就是空应答，强制询问（如狂戾之心）会无限重问、把整局卡死。
   改成：**超时优先用这一段的 `超时默认`，没有就按「不发动」收尾**；只有「非超时却给了空应答、
   又不能取消」这种异常才重问本段。
   **第二次审查再改**：这句「异常空应答重问本段」与旧实现不符（旧实现是强制段自己补弃 / 补取），
   已改成「按没选继续，交给 校验 / 答完 / 结算」，带段级校验的（审判 / 展示 / 荒神）仍会驳回重问。见 5.7。
3. **军神威光挪到 P2**：它现在的「返回」是客户端 `_军神威光返回` 硬编码；而且第二段「非法星石组合」
   目前是退回第一段重问。搬进框架前要先定「非法提交＝重问本段还是退回上一段」的口径
   （框架现在只提供「空应答＝回退」，没有「校验失败＝回退」）。为了 P1 保持「行为完全一致」，先不迁。
4. **神智污染**：单段「确认」用框架收益不大，但验证了两件事 ——「预览基准 / 预览类型」能原样透传，
   以及结算回调里能直接改 `harm`。原来靠引擎每轮的 `step` 防重问，现在改成 `harm["神智污染已处理"]`
   标记（跨询问更可靠，不会被钩子轮次清零影响）。
   **注意**：置标记那一步必须放行「链进行中」的重入（否则重入被守卫挡掉、回复没人取，见 5.6 第 7 条）。
5. **「空应答」的判定口径**：框架里「空」=`args` / `card_ids` / `dst_ids` 全空。
   注意选项值 **0** 是合法答案（如戾气调为 0），因为 `args` 非空，不会被误判成「取消」。
6. **弃牌合法性**：扭曲之爱把「弃几张」的校验放在结算里（`min(2, 手牌数)`），
   框架不替它校验 —— 框架只负责「问」和「回退」，业务校验仍归角色（与设计一致：副作用和校验都在结算）。
7. **框架能力是迁移逼出来的**：迁军神威光时才发现三个真实需求 ——「选①就不用问第二段」（→`跳过`）、
   「第二段超时按①结算」（→`超时` 回调）、「非法星石组合退回第一段」（→`校验` + `校验失败回退`）。
   这三个能力最后都做进了框架（`7eec202`），没有留在角色里各写一遍。
8. **军神威光口径保持不变**：非法组合仍然「退回第一段」，没有顺手改成「重问第二段」；
   要改属于交互优化，得单独提需求（记在第 8 节）。
9. **魔纹融合**：框架不管引擎的 `step`，所以结算里仍自己置 `step = STEP_DONE`，
   挡住「返回 URGENT 后引擎重入钩子」那一下（这是引擎层的规矩，框架不接管）。
10. **魑魅魍魉收尾**：`选项可返回` 指示器键彻底删除，客户端只认 `allow_back` ——
   至此「多步回退」全仓只剩一套机制（`f1d1429`）。
11. **踩坑：新增的询问字段必须登记进 `proto_schema.gd`**。`allow_back` 一开始只塞进了询问命令的字典，
   字段表里没有它 —— 单机（进程内直连）能跑，真实联机会被编解码静默丢掉，客户端永远摆不出「返回」。
   已补 `Command` 表 `65: allow_back`（`96f86b2`）。**以后往询问命令里加任何键，都要同时加字段表。**

12. **框架不接管「URGENT 之后的重入」**：`p_special_skill` 结算里压了状态（扭曲之爱摸牌）再返回 `URGENT`，
    引擎会把同一个 `p_*` 再调一次；那时框架的链已经结束，`多步询问` 会**新建一条链**、把第一段重新问一遍。
    处理：角色自己加一次性标记（扭曲之爱 `_扭曲已结算`，魔纹融合沿用 `step = STEP_DONE`）。
    这条写进约定：**结算里压了状态并返回 URGENT 的技能，必须自己挡住重入**；以后框架可以考虑提供统一的
    「结算后一次性拦住下一次调用」开关，但要先定清楚「新触发」和「重入」怎么区分。
13. **客户端本地分层也统一了**（P3，`eeb0888`）：原来苍白之月 / 圣光爆裂 / 自动填充各有一套
    「进入第二层 / 返回第一层」函数 + 一个 bool 标志（6 个函数 + 3 个 bool）。现在统一成
    `_本地二层` 一个状态 + 三个通用函数；进入时把第一层选项与「返回」回调抄下来，退出时原样还原。
    **行为差异只有一处**：退出第二层时统一清空已选的牌/目标（原来只有苍白之月清），
    对另外两个技能是更保险的做法（回到第一层本来就要重选）。
    这类「不需要服务端再问一次的分层」属于客户端交互，不进 `多步询问` 框架。
14. **第一层选项有两种形态**：苍白之月 / 圣光爆裂 传的是 `_skill_arg_choices`（原始选项），
    自动填充传的是询问进来时存下的**归一化选项项**。统一还原时按「有没有 `文本` 键」区分，
    不能一律再过一次 `_选项项`（否则自动填充的第一层会变成一堆空按钮）。修正见后一个提交。
15. **单问技能迁进来也有收益**（P4，`3d9c5dd`）：战纹碎击 / 双重回响 各只有一个询问，但迁完后
    两个自有阶段变量（`_zhan_wen_step` / `_hui_xiang_step`）都删掉了，回退/超时/取消统一由框架管；
    其中「不能选当前受伤者」用**段级 `校验`**（不过关重问本段）表达，替代了原来的递归重问。
    两个技能都仍保留自己的一次性标记挡 URGENT 重入（`step = STEP_DONE` / `shuangChongHuiXiangUsed`）。
16. **框架补了两个能力**（`af906a1`）：①段字段可以是 `Callable(答案)`（`需牌`/`需目标`/`选项`/`牌上限`/
    `牌白`/`目标白`/`预览基准`），用于「第二步的白名单要看第一步弃了什么」；②`多步询问进行中(链号)`，
    给钩子类技能挡住「别的同类事件插进来」。水影是第一个用上这两个能力的技能。
17. **框架又补了三个段能力**（`0e05fae`）：`问谁`（这一段问谁，默认自己）、`答完`（这一段答完立刻结算，
    可压状态并返回 URGENT/WAIT；段号已推进，重入从下一段继续）、`取消`（整条链取消时的回调）。
    剑守誓言 10803 是第一个用上「答完」的技能（牌库顶取牌必须在两段之间做，第二段的选项依赖取到的牌）。
18. **段可以自带技能号**（`9ba0b98`）：一条链里两段是不同技能时（圣炎收尾 4305 → 圣炎祈愿 4307）不串号。
19. **取消也是结算 / 更多 Callable 字段**（`7966509` + 本次）：①「取消」回调可以返回 `URGENT/WAIT`，
    「不这么做」本身要结算的技能（醋意休心：不弃法术牌就吃 2 点伤害 + 水晶）用它表达；
    ②`询问文案`、`预览目标` 也支持 Callable(答案)。
20. **超时也走取消回调**（本次）：以前超时按「不发动」收尾时**不**调段的「取消」回调，
    而英灵召唤这类技能「超时也要把已经付过能量的横置处理掉」——现在超时和手动取消走同一段逻辑。
21. **框架加「收尾」回调**（本次）：结算里压了状态（返回 URGENT/WAIT）时，引擎重入会先跑 `收尾`，
    再交还给角色。启示 9604 就是这种：第二段答完要摸 1 张牌，摸完还要看摸到了什么才决定要不要取消转移。
22. **循环段 + 可重复收尾**（本次）：①段字段 `重复`（为真留在本段重问、答案就地覆盖）——
    宝珠推进 / 糖果推进这类「对每个目标各问一次」的循环链以后就能直接迁；

#### 5.8.7 经验与防复发

1. **脚本语法坏 → 界面用例假通过**：`load()` 对语法错的脚本仍返回对象，窗口 `get / call` 全 `null`、断言里的 `bool(null)` 是 `false`。
   已在 `selfCheck.gd` 加关键脚本 `reload()` 预检（坏了退出码 2），并记录：**排查时插的打印，收尾必须整段删干净**。
2. **headless 下 `create_timer` 不推进**，用例里等时间一律按帧轮询；否则整个自检会挂死。
3. **客户端发完应答会延迟 0.15s 清界面**（避免闪屏），用例不能只等 2 帧。
4. **对比修复要按「失败断言条数」**，不能只看「用例数」：修好 20 条断言，失败用例数可能一个都不变。
5. **手拼 harm 必须带 `card_id_instance`**，否则引擎按虚牌（无命格）处理，同命格类技能全部失效。
6. **文案以表为准**：用例里不要写死技能文案；先查技能表，再决定改用例还是改代码。
7. **排查要有单用例入口**：`--case=` 把一次迭代从 90 秒压到 8 秒，是这轮能定位到根因的关键。

## 6. 非目标与风险

- **不做全量重写**：存量 50 个多步技能保持现状，只在被改动时才迁移。
- **不合并 A 与 B**：客户端本地（A/D）与服务端分段（B/C）是两类需求，框架只在「需要回退的分段」上统一。
- **不改既有行为**：P1 的验收标准是「行为与现在完全一致」，不是「顺手优化体验」。
- **「攒应战」不通用化**（2026-11-10 决定）：式神咒束 3301 / 阴阳转换 3306 的那套
  「选效果 + 选应战牌 + 选反击目标，本地攒着一次提交」看着像多步询问，但它是**攻击应战**的一条专用链：
  依赖攻击牌 / 攻击者 / 本次伤害 / 能否用圣光 / 同命格 / 反击目标合法性，且只有这 2 个技能用。
  抽成通用框架等于把应战语义搬进多步询问，收益低、回归风险高 —— 保持现状，只在改动这两个技能时按需整理。
- ~~暂不做「循环段」~~ → **已做**（`0fb112a`，`重复` 段；宝珠推进 / 糖果推进是首批用例；
  答完压状态的情况用「延迟判重复」补上，`d8fd7eb`）。
- ~~段表是静态的~~ → **已做**（段字段支持 `Callable(答案)`，侍奉之道 / 水影 / 醋意休心都是实例）。
- **分发器不强行合并**：一个函数里跑多件互不相干的技能时，按技能拆成多条链（噬神者 / 异教徒），
  但**不**把几件技能合成一条链 —— 链号＝技能号，进度各记各的。
- **网络包体**：多步链每段一条 `CmdReq`，与现在相同；不引入新的长连接状态。
- **重连**：进度在房主进程内存里，房主掉线本局就结束（与现有规则一致），不需要持久化。
