### 2.2 盖牌/子弹相关的数据语义

- 38 的「子弹」是**盖牌槽里的实际牌**，不是计数器：3801 开局 6 张面朝下；3802 移除 1 个后按该牌系别结算；3804 提炼时把 1 张手牌面朝下补成子弹。`covered_max=6` 同时是上限和 UI 数量上限。
- 3804「若你未拥有【子弹】」应判断 `cover_cards.is_empty()`，不是 token num（38 没有槽 0 token）。
- 3802「光系或暗系子弹视为任一系别」：子弹牌本身是 `light`/`darkness` 元素；需要在移除时保存「视为的系别」或直接选择分支。数据表没有字段承载该选择，属脚本/UI 逻辑。
- 46 的灵涌是槽 0 token，4604 增加、4605 满时清空；93 的元子是槽 0 token，9301 增加、9302 花 2、9304 把雷击的宝石改成元子（受上限 3 限制）。
- 这三名角色的指示物上限都应从 `player.tokens[x]["max"]` 读，不要写死 4/3/6（角色表是唯一权威）。

合计 **37 颗需要专用提示（P0+P1），约 60 条文案**；22 颗不需要。

### 4.2 建议文案样例（与现有提示风格一致）

- 选目标：`请选择 {n} 名目标对手` / `选择 1 名队友`。
- 弃牌：`弃 {n} 张牌【展示】` / `弃 1 张法术牌【展示】`。
- 支付：`支付 1【水晶】` / `支付 1【宝石】`（费用写法沿用现有技能表）。
- 伤害变化：`本次攻击伤害 +2` / `对 {dst} 造成 2 点法术伤害`。
- 额外行动：`额外 +1【攻击行动】` / `额外 +1【法术行动】`。
- 占位符：`{n}` 张数、`{src}` 发起者、`{dst}` 目标；多条提示用「提示 / 提示2…」逐列写，中间空列不要左移（《技能维护约定》§提示列）。
- 选项文案不要用括号解释；固定分支不可省略、不可用项保留 `enabled=false`（本批技能的二级选项见 4103 支付、4606 选技能、7804 是否移除星石、8704 是否移除星石、9704 二选一）。

### 4.3 数据流程问题（需主代理处理）

本批 R 任务的 `files` 只有角色脚本 + 测试；提示列只能由 DATA 任务改设计表并导表，而 DATA 依赖 13 个 R 任务全部完成。也就是说：

- R 任务完成时**无法**同时满足计划 DoD 的「该角色所有多步询问的提示已配」；
- 若等 DATA 最后统一配，提示与逻辑会分离验收，且「提示不覆盖技能说明」这类回归只能在最后发现；
- 技能指示器同理（`const.gd` 只在 CLIENT 的 `files` 里）。

建议主代理二选一：
1. 把 DATA 拆成「每批数据」任务（files 仍只含设计表/CSV/DataTables），每批角色实现前先配提示/指示物；
2. 或明确 R 任务验收只卡服务端行为 + 测试，提示/指示器全部由 DATA/CLIENT 在批次末统一补齐，并在 R 验收记录里注明「UI 文案待 DATA/CLIENT」。

## 8. 公共能力缺口（代码事实，基线 aef3450）

### F1 魔弹体系泛化

- 基线：`battle_role.gd` 的 `missile_targets()` / `has_missile_mastery()` / `v_missile_fusion()` / `cast_missile_fusion()` 把「地/火」写死；`role_modao` / `role_spmodao` 另有 `_can_remissile`。
- 工作区 F1（未验收）已加 `missile_fusion_elements()` / `can_use_as_missile()` / `missile_fusion_hand_ids()`，但**只有一组系别**，同时用于「主动使用」和「响应传递」。
- 本批需要三组能力，建议 F1 接口区分：
  1. 主动使用：87（雷/火）、107（地/风）；
  2. 仅响应传递：47（水/火）——4703 原文「传递」；
  3. 独立入口：106（弃 2 张同系牌，不经过魔弹融合）。
- 客户端 `battle_mobile.gd` 的 `地火可作魔弹角色 = [8, 76]` 与 `_是魔弹融合出牌` 仍按角色号写死；F1 验收应要求客户端改为服务端牌白名单驱动，或至少由 CLIENT 明确过渡方案。

### F2 额外行动与行动计数

- 已有：`BattlePlayer.additional_actions` / `add_action` / `clear_additional_action`；`STurnEnd` → `SAdditionalAction` → `SActionPhase(is_extra)`；`action_commands()` 的 `is_extra` 与 `extra_cause`；`role_jiansheng.attack_count` 是角色私有计数。
- 缺：统一的每回合「攻击/法术/特殊/额外」计数与只读查询；`push_after_action()` 的 `p_after_attack / p_after_magic / p_after_special` 上下文只有 `player/card_id/dst/special_action`，**没有 `is_extra` / 行动序号**；额外行动的「目标限制」与「牌型限制」只有剑圣 `action_card_ids` 一个模板，没有通用配置。
- 需要：F2 在 `battle_engine` / `battle_player` / `battle_role` 加计数与「行动结束」通用钩子；`action_card_ids` 支持 3803（同系）、4101（技类）、10702（魔弹）、10704（目标限制）、10804（目标限制）。
- 本批使用点：4103（第 3 次行动）、4104（每次额外行动结束）、4501（技类额外攻击）、4503（第 1/2/4 次攻击）、3803（同系额外攻击）、10702/10704、10803/10804。

### F3 指示物 / 盖牌通用能力

- 已有：`_按表初始化标识物()`（槽 0/1 token，槽 2 cover_cards_max）、`player.tokens` / `cover_cards`、`role_token_def`、通用 UI。
- 缺：38 开局 6 张子弹的初始化（脚本责任）；盖牌槽与 token 槽的一致性校验（若角色表两处上限不一致，槽 2 覆盖 `covered_max`）；`子弹` 的「正面朝下」可见性（A1）。
- 本批使用点：38（子弹 6、3801/3802/3804）、46（灵涌 4、4604/4605）、93（元子 3、9301/9302/9304）。

### F4 基础效果目标 / 触发钩子

- 已有：`engine.add_basic_effect / remove_basic_effect`，都会压 `p_basic_effect_change`（`add` / `remove`）；`p_basic_effect_change` 在天使【天使羁绊】、4602 等场景可区分 doer。
- 缺：
  1. `add_basic_effect()` **没有目标资格校验**（4601「无法成为基础效果目标」）；圣盾/虚弱/中毒/封印/赐福的每个施放点都要统一走 `v_basic_effect_target`（或等价钩子），否则只改一处会被其他路径绕过；
  2. 没有「触发并结算完成」的钩子：`p_basic_effect_change` 只有 add/remove，不能区分「触发后移除」与「被拿走/被移除」；4604 需要 `p_basic_effect_triggered` 或 remove 带 `triggered` 标记；
  3. 客户端目标置灰（4601）需要 CLIENT 配合。
- 本批使用点：46（4601/4602/4604/4605/4606）、78/106（放置基础效果的一般路径）。

### F5 跨角色独有技
