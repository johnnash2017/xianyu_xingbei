## 0. 背景与目标

现状问题：提示文案有**两套独立决策树**（询问时的 `_进入技能询问` 与切换选项后的 `_刷新二级栏提示`），
选项开关还要穿过「引擎组装 → 协议编解码 → 客户端归一化」三层，任何一层漏抄就静默失效
（已踩：`卡牌`、`不改提示`；放逐提示两次修不完整）。

目标：

1. 提示文案的**决策**只有一处：服务端在询问时算好「步骤文案」，客户端只在选项显式声明时覆盖。
2. 提示文案的**数据**只有两处：技能表「提示」列（技能专属）、文本表（公用句式，中文 id）。
3. 新增技能 / 改文案不碰客户端 UI 代码，只配表 + 一行取文案。
4. 迁移前后**功能完全一致**：该显示的步骤、代价、选择要求、选项说明一条不少。

**非目标**：不改提示条 UI 排版、不改头像指示器数值逻辑、不改协议既有字段语义；不承诺文案逐字不变（见 §8）。

## 1. 目标模型

### 1.1 提示文本只有两种

| 类型 | 内容 | 来源 | 何时变 |
| --- | --- | --- | --- |
| **步骤文案** | 这一步要玩家做什么（含代价 / 对象 / 长整段说明） | 角色显式给，或服务端自动取「提示」第 0 条 | 选项显式覆盖时才变 |
| **技能说明** | 技能本体效果 | 技能表「说明」 | 不随选项变 |

本地流程（提炼 / 购买 / 特殊行动 / 各种第二层选项）用各自专用文案，单独短路。

### 1.2 客户端规则（4 条，替代现在 11 个分支）

```
1. 本地流程 → 专用文案
2. 选中项带「提示」 → 用它（%d 填已选参数）
3. 选中项标「独立技能」 → 用该选项技能的「说明」
4. 其余 → 询问时下发的步骤文案（ask_text）；为空 → 技能说明 → 自动句
   （自动句：【技能名】：选 N 张牌 / 选 N 名目标 / 选择一个选项）
```

### 1.3 服务端职责（复杂度收在一次）

`BattleRole.询问()` 统一算「步骤文案」：

- 角色显式传了文案 → 用它（一般写 `提示原文(技能号, 序号)`）；
- 没传：响应技能 → 指示器 `提示序号` 对应那条；其他技能 → 技能表「提示」第 0 条；
- `ask_prompt` 与 `ask_text` 合并为 `ask_text`；协议旧字段保留一期兼容，客户端只读一个。

### 1.4 选项字段（最终）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `提示` | str | 选中后本步文案（可含 `%d`）；不填＝保持步骤文案 |
| `独立技能` | bool | 选中后提示换成该选项技能的说明（替换旧 `_固定父说明` 启发式） |
| `技能号` / `技能组` | 现有 | 只用于悬停说明，不再影响提示条 |
| `卡牌` / `需牌` / `需目标` / `牌白` 等 | 现有 | 不变 |

删除：`no_prompt_change`（默认就是保持）、`选项提示文案`（指示器模板，迁表）。

## 2. 数据表设计

### 2.1 技能表「提示」列

- 现有 `提示`…`提示8` 导入时合并成数组；导表器改为**收集所有 `提示*` 列按数字排序合并**，
  所以直接加 `提示9`、`提示10` 即可，不改代码。
- 序号约定不变：`提示`=0、`提示2`=1……；第 0 条 = 该技能的默认步骤文案。

### 2.2 文本表（公用文案，中文 id）

新增访问器 `GConst.文本("id")`，缺 key 返回 id + 调试告警。首批 id（约 10~15 条）：

| id | 内容（示例） |
| --- | --- |
| `提示_选择一张手牌` | 选择 {n} 张手牌 |
| `提示_选择目标` | 选择 {n} 名目标 |
| `提示_选择一个选项` | 请在技能栏里选择一个选项 |
| `提示_交给队友` | 选择 1 名队友交付 |
| `提示_弃牌通用` | 弃 {n} 张牌 |
| `提示_展示弃牌` | 弃 {n} 张牌【展示】 |
| `提示_选项已选好` | 选项已选好 |

### 2.3 访问器（只用三个）

```gdscript
提示原文(技能号, 序号)          # 技能表提示列 + 占位符
文本(id)                       # 文本表 + 占位符
填文本(模板, {src,dst,n,s1…})   # 上面两者共用
```

### 2.4 导表器

`addons/excel_to_gd`：`提示*` 收集合并；文本表保持 `id,文本`（允许额外备注列，不导出）。
导表后对比 `DataTables.gd`，只允许提示数组变化。

## 5. 迁移映射与规模

| 现有 | 新 |
| --- | --- |
| 放逐整段提示 + 正面选项不改提示 | 步骤文案=技能表提示列；选项不声明 → 天然不变（删 `no_prompt_change`） |
| 审判弃牌专属文案 | 步骤文案=提示列 |
| 三秒原则「弃 X 拿 X 魔弹」 | 选项带 `提示` 模板 |
| 圣光爆裂选中后显示该档说明 | 选项带 `提示` |
| 迅捷/威力赐福响应 | 服务端算好文案放步骤文案 |
| 御刃/共振选项带技能号 | 只用于悬停；提示保持步骤文案 |
| 蓄力一击/气绝崩击/怒火压制/魔纹融合 | 选项标 `独立技能` |
| 7803/7804/多份额外行动 | 步骤文案由服务端下发（表里配） |
| 圣光爆裂第二层 / 军神威光第二层 / 元素射击 | 本地流程不变 |

规模（已扫描）：

- 56 个角色 / 帮助脚本含 `询问` / `ask_skill`，共 **220 个调用点**（生成器口径，含 `engine.ask_skill`）；其中 **60 个**仍带显式中文长文案（迁移清零目标）；
- 选项字段：`skill_id` 23、`说明` 10、`card_id` 47、`label/text` 178；
- 技能指示器里提示条文字模板仅 **1 条**（`选项提示文案`）；`选项提示` 是头像数值配置、不受影响。

## 7. 验收标准（硬性）

1. **快照一致**：同一组上下文输入，迁移前后文案逐字相同（“功能完整”的主要证据）。
2. **全量自检**：70 例仍 66 通过（4 个既有失败不增不减）。
3. **清单覆盖**：220 个询问点在 `提示文案清单.md` 里全部标注来源（表 / 文本 id / 自动句），无遗漏。
4. **扫描清零**：角色脚本里不再有硬编码提示长文案（扫描规则：询问 / 选项附近的中文长字符串）。
5. **id 校验**：代码引用的 `提示原文(技能, 序号)` / `文本(id)` 全部存在。
6. **导表干净**：`DataTables.gd` 差异只涉及提示数组。
7. **使用简便**：新增技能配置提示 ≤3 步（表里填提示列 → 代码 `提示原文`；要覆盖选项 → 填 `提示` / `独立技能`）。
