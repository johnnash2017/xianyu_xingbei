### 2.1 94 记录者（本轮重写 `role_jiluzhe.gd`）

修复：

1. **阻断**：`引稽编鉴` 的询问字符串引号未闭合（整个脚本加载不了）——随重写一并修掉。
2. **选项永远为空**：原代码在 `if 牌 == null: continue` 之后把 `选项.append(...)` 写在 if 块里（缩进错位），
   三处「选项列表」实际上永远是空的（9402 选牌、9404 档位都点不出来）。重写后选项在循环体里正常追加。
3. **知行合一 9402**：
   - 选牌与「弃 1 张手牌」合成**同一条询问**（约定 22），不再先选牌再单独弃牌；
   - 选中的牌加入手牌后给一份 `direct` 的「只能用这张牌」的额外行动（同 7803 / 9303 的写法），
     行动结算完成（`p_action_end` 的 `extra_cause == 9402`）才把剩余展示牌弃掉、+X【史料】；
   - 额外行动被放弃时在 `p_turn_end` 收尾：这张牌不算白拿，按技能口径弃掉（原来会白留一张）；
   - 取消 = 不把展示牌作为行动发出：两张都弃掉、+2【史料】（原来取消时两张牌凭空消失）。
4. **稽古识典 9403**：不再用「先压弃牌状态、再同步发史书」的写法；改为在当前流程里先问「弃 1 张牌」，
   拿到答复（或超时补手牌第一张）后再发【史书】，顺序与原文一致；【史书】从 `移除牌堆` 取回后再进手牌
   （约定 13，原来被【以史为镜】移出后就再也发不进来）。
5. **秘境万象 9406**：伤害目标数按 `min(X-3, 在场人数)` 取（约定 23），不再在 X 很大时卡到超时；
   取消/非法目标不再静默补人。
6. **古今互鉴 9408**：交换条件改为「手牌 ≥ 2」；`X` 与所选手牌张数、遗迹数一起校验；
   稽古识典的弃牌放在技能最后收尾，避免「+2 史料后多压一层状态把交换询问挤掉」。
7. **引稽编鉴 9409**：攻击目标交牌改用技能询问本人选（原来走 `RespondType.Discard` 再把手牌第一张
   当遗迹，弃牌日志和拦截钩子都跑错）；交换档位 1~2 与手牌张数一起校验；结算完继续走 9404。
8. **遗迹论破 9404**：从 `p_before_attack` 挪到 `p_timeline_1`（原文「主动攻击时①」）；标记在攻击开始时复位；
   与 9409 同一处 ① 时点串行（9409 先、9404 后），不再互相吞掉。
9. **传说之地 9401**：开局取牌改走 `engine.移除牌库顶`（会广播快照），仍然面朝上作为【遗迹】。

遗留 / 口径待确认：

- **9404 的 X 上限**：技能原文没有上限，`遗迹` 上限 8，但设计表「按钮」列只配了 1/2/3 三档，
  所以现在只能移除 1~3 个。要支持 X>3 需要设计表补「按钮4~8」后重新导表。
- **9407 以史为镜**：「转移拥有者 / 因技能放置在角色旁」两种情况没有落点——实际对局里【史书】只会
  留在记录者手上（9409 只交换手牌与遗迹、秘境万象直接移除），暂不实现。
- 9402 选到【圣光】这类只能响应的法术牌时，给出的额外行动点了会被驳回（引擎不接受主动施放【圣光】），

##### 2.5.2 叛逆之墙：不许把第二层【圣盾】叠到目标面前（需求方实测）

现象：目标面前已有【圣盾】、同时还有别的基础效果（中毒 / 封印 / Tricky…）时，选「交换 别的那张」，
手里那张【圣盾】就顶了上去 —— 目标面前出现两层【圣盾】。这与引擎的 `base_v_shield`（目标已有
【圣盾】/【天使之墙】就不能再放【圣盾】）是同一件事，只是 8602 走的是「交换」不是「打出圣盾」，
没经过那道校验。

修法：按「换完之后目标面前还剩几张盾」判，而不是按「换之前有没有盾」判——

- 服务端 `v_magic_skill`（8602）：遍历目标的基础效果，除被换出的那一张外只要有任意一张
  「视作【圣盾】」（卡名【圣盾】或带【天使之墙】701）就驳回 `GE_BASIC_EFFECT_ALREADY_EXISTS`；
  目标只有那一张盾时，把它换出来是合法的（换完仍是 1 层）。
- 客户端 `battle_mobile._基础效果选项`：技能指示器配 `"不放重复圣盾": true`（目前只有 8602）时，
  按同一条规则不列出「换完还剩盾」的选项，避免玩家点了才被「操作无效」驳回。
- 新增 `_是盾类牌(card)`（battle_mobile）/ `_是盾牌(cid)`（角色脚本）两个同口径判定。

##### 2.5.3 T-r-i-c-k-y! 改成「点头像查看」（需求方要求）

- 第 1 段不再用选项列「查看 X 的 Tricky」，改成**选 1 名角色**：`目标白 = _垂迹候选()`
  （面前有【Tricky】的人；每人至多 1 张，所以「人 ↔ 那张」一一对应），答完按 `_Tricky序号` 取那张。
- 客户端新增 `battle_mobile._垂迹头像提示()`：技能询问（mode 3）+ 技能号 8604 时，
  只给**已点选**的那名角色头像写 **「查看Tricky」**（候选只靠点亮表达可点）；选完进弃牌段时选择清空、提示消失。
- 第 2 段（弃 1 张同系牌）在原拥有者头像上写「2 法术伤害」：服务端带
  `预览基准 2 / 预览类型 HarmType.Magic / 预览目标 [原拥有者]`，客户端走
  `_预览伤害头像提示` 的通用通路现算。该头像不是可点选目标（`need_target = 0`），所以不占黄框选中态。
- 手里没有同系牌时这一问也照常弹（不再「跳过」），只是不要求选牌、提示条说明原因。
- 技能表 8604 的「按钮」列（`查看 %s 的 Tricky`）因此不再被代码调用；表没动，是否清理由需求方决定。

##### 2.5.4 神秘伏笔：选项与目标同一问（需求方要求）

原来分两段问：先选「放 1 张 / 放 2 张」，取完牌库顶再另弹一问选 X 名角色（两次确定）。

- 合成一段：选项各自带 `need_target`（＝这项要放几张）与 `targets`（当前能放【Tricky】的人）。
  技能指示器给 8603 配 `"攻击结束二选一": true` —— 这是 mode 3「**选项自带需牌 / 需目标**」那条现成通路
  （名字来自 10804 那批，机制不限于攻击结束），选中一项后直接点 X 名角色、按一次「确定」一起提交。
- 副作用全挪进结算：取牌库顶、放置、【报错】；段里只收答案。
- 校验：张数 1~2 且不超过牌库 / 可放人数；目标数＝张数、不重复、都能放。
  超时（`可取消=false` + `超时默认 [1]`）按「放 1 张」结算，目标按座位顺序补 1 名。
- `_伏笔张数` 这个跨段状态随两段合并一起删掉。

`push_show_hand(pid, cards)`：只发一条 `Card.Show` 广播、不压这个钩子，封印就永远不触发
（言灵术的【言灵】就是这么漏的）。

本轮补上（都是「从手里拿出来、面朝上给全场看」）：

| 角色 | 位置 | 说明 |
| --- | --- | --- |
| 80 神秘学者 | 言灵术：放【言灵】（`push_show_hand` 压在摸牌之后，先结算展示响应再摸牌） | 用户报的 bug |
| 80 神秘学者 | 言灵术：额外弃 1 张同系牌【展示】 | 压最后 + `URGENT`，封印响应在行动结束之前 |
| 80 神秘学者 | 守护灵：补的那张手牌面朝上作【言灵】 | `take_from_hand(..., true)` |
| 86 捣蛋萝莉 | 8601 天使？（牌本身当圣盾）、8602 叛逆之墙（手牌圣盾） | 两处都已是 `true` |
| 96 传教士 | 传道：自己弃的【展示】牌 / 持有者弃的【展示】牌 / 启示摸到并【展示】的那张 | 前两处 `take_from_hand(..., true)`，启示补 `push_show_hand` |
| 109 仲裁者·圣 | 善恶必计 / 天罪 / 罪迟必到：基本牌面朝上【展示】放到天平 | `_放牌` 里统一压钩子 |
| 92 铸律者 / 111 红衣主教 | 信仰重铸放宝珠 / 圣律威压弃牌 / 驱魔式弃牌 | 原本就带 `已展示=true`，本轮核对确认 |

**故意不加**（不算「从手中展示出」，加了会让封印误触发）：

- 80 禁忌秘法：放上去的是**别人手里弃掉的牌**，不是自己从手里展示的；
- 81 侍奉之道：展示的是盖牌区的【影】（不是手牌）；
- 86 Trick or Treat：展示的是早就放在场上的暗【Tricky】；
- 86 T-r-i-c-k-y! 的「查看」：只发给本人看，不是公开亮牌。

#### 4.11.1 全仓排查（不只 9 个新角色）

排查口径：凡是「牌面会被别人看到」的入口，都可能漏 `p_show_hand`。按下面五类扫了一遍全仓：

| --- | --- | --- |

### 4.12 统一「公开亮牌」入口（本轮）

之前亮牌有四种写法混着用：手写 `Card.Show` 广播、`take_from_hand(..., true)`、两者拼、`push_show_hand`。
谁漏了第二种，就是「牌看得见、封印不触发」——言灵术就是这么漏的。现在收成一套：

| 引擎入口 | 用途 |
| --- | --- |
| `展示牌(pid, cards, 持久)` | 非手牌来源（牌库顶 / 盖牌区 / 弃牌堆 / 场上），只广播 |
| `展示手牌(pid, cards)` | 手牌公开亮出：广播 + `p_show_hand`（封印触发点） |
| `私下看牌(pid, cards)` | 只给本人看，不广播、不压钩子 |
| `展示手牌并弃(pid, cards, ctx)` | 亮 + 离手 + 进弃牌堆 + 日志 |
| `展示手牌进盖牌(pid, cards, cause)` | 亮 + 离手 + 面朝上盖牌 |

- 9 个新角色已全部迁移：脚本里**一处手写 `Card.Show` 都不剩**（`grep CardMsgType.Show` 为空）。
- `engine.展示牌库顶` 内部也改成走 `展示牌`，行为不变（牌库牌不算展示手牌）。
- 口径写进 `项目文档/技能维护约定.md`「公开亮牌：只走引擎的三个入口」。
- 新增只读巡检脚本 `tests/查展示钩子.ps1`：列出还在手写广播的位置并标注同函数有没有展示钩子。
  存量角色还有约 20 处手写广播（牌源都是盖牌区 / 牌库 / 别人的弃牌 / 私有查看，不是 bug），
  属于**待迁移**清单，不影响行为。

### 4.13 神秘学者：面朝上的牌统一显示为「言灵」

状态区里【言灵】的图标名字原来取卡名（玩家看到的是「火焰斩」之类），看不出这是言灵。
现在走已有的角色特性 `GConst.角色特性[80]["面朝上盖牌名"] = "言灵"`：

- 图标名字固定「言灵」，不显示原本卡名（图标本身还是那张牌的卡面，看得出是哪张 / 什么系）；
- 悬停说明也改成「面朝上的盖牌（言灵·火 系）」——保留系别（真言术要按系别挑），不露原卡名；
- 客户端这条配置现在支持两种写法：带 `%s` 的按系别填（结界师「结界·%s」）、不带 `%s` 的整块当名字（「言灵」）。

### 4.14 「盖牌当手牌」改由服务端快照驱动（真言术用）

真言术要「在盖牌区点一张【言灵】直接出牌」，靠的是引擎既有的「盖牌视同手牌」能力
（`BattleRole.盖牌可当手牌()` → `BattlePlayer.has_hand_card` / `remove_hand_cards` 都认盖牌）。
但客户端原来把这条写死在精灵射手（role_id == 32 且横置）上，别的角色用不了。

这轮改成数据驱动：

- `BattlePlayer.to_proto` 新增 `cover_as_hand`（取 `role.盖牌可当手牌()`），随对局快照下发；
- 客户端 `_盖牌视同手牌()` 直接读这个字段，删掉 role 32 的写死判断（精灵射手行为不变）；
- 神秘学者覆写 `盖牌可当手牌()`：只在真言术「把这张盖牌当牌打出去」那一瞬间为 true。

于是「盖牌能不能当手牌」由服务端说、客户端照做，精灵射手的行为完全不变。



### 4.15 真言术交互（标准技能写法，无客户端特判）

技能栏里 8003 这一项按「和别的技能一样」的方式声明要选什么：

```gdscript
{"type": MagicSkill, "id": 8003, "need_card": 1, "need_target": 1,
 "card_source": GConst.CardSource.Cover, "cards": 可用言灵, "targets": 全部角色()}
```

于是客户端点技能按钮就**直接进选牌状态**：盖牌区亮出来（非言灵的置灰）+ 头像可点，
选 1 张【言灵】、点 1 名目标、按一次「确定」——这一次提交里就带着「哪张言灵 + 打谁」，
服务端 `v_magic_skill` 复核后 `p_magic_skill` 直接把它当那张牌打出去：

- 走引擎新增原语 `BattleEngine.技能出牌(pid, 种类, cards, dsts, cause)`：
  原生 `_do_attack` / `_do_magic`（视为 / 应战 / 命中 / 伤害 / 行动结束响应全照常），
  但记成**额外行动**（不消耗攻击 / 法术行动）、**不压回合结束**；
- 出牌那一下用同步窗口 `_真言行动中` 打开「盖牌当手牌」，引擎 `has_hand_card` /
  `remove_hand_cards` 就能直接认这张盖牌并从盖牌区删掉；牌不搬进手里；
- 神秘学者覆写 `盖牌可当手牌()`：只在真言术「把这张盖牌当牌打出去」那一瞬间为 true。
	- 客户端的表现由 `GConst.技能指示器[8003] = {"当作卡牌": true}` 驱动（可复用，不是按角色号写死）：
	  · 没选牌时头像全灰；
	  · 选好牌后按**那张牌**的出牌规则点亮目标（直接复用普通出牌的 `_可选_行动`，攻击只亮敌方、法术按法术目标规则）；
	  · 点头像＝立刻把这张牌打出去，不再要求按「确定」。
	- 修两处「只亮目标、没真按卡牌逻辑走」的漏：
	  · 攻击牌从盖牌区打不出去 —— `v_magic_skill` 复核那张牌时也要打开「盖牌当手牌」的窗口
	    （`v_attack` / `v_shield` 这类校验走 `has_hand_card`，窗口没开就会被判成「手里没有这张牌」）；
	  · 【魔弹】头像上的「N 法术伤害」——`_魔弹头像提示` 原来只认 mode 1，补上「当作卡牌」的发动技能状态。
	- 盖牌当手牌用的可点性统一成两条：① 这一步放行它当手牌；② **这张牌本身这会儿能打出去**
	  （复用普通出牌的 `_可主动使用牌`：放行动作 / 禁法术 / 【圣光】 / 圣盾·虚弱·中毒·魔弹有没有合法目标）。
	  修掉了「所有人都有【圣盾】时，盖牌里的【圣盾】还能点」的漏判 —— 现在它和手牌里的【圣盾】一起置灰。
	- 结算后节点修正：真言术「当作卡牌」打出的那张牌，行动结束响应（妖精秘术 / 真言压制 / 其它角色的 p_after_×）
	  整组**延后到 p_action_end 之后**——引擎 `_push_action_end_hooks(..., 延后响应=true)` 由 `push_after_action`
	  在「技能出牌」期间自动启用（LIFO：p_action_end 先跑）。于是：
	  ① 没有第二段（不是咏类/法术牌、且没有【秘术】）→ 第一段结束就问响应；
	  ② 有第二段（咏类/法术牌，或确认移除 1 点【秘术】）→ 第二段的 1 点法术伤害结算完才问响应；
	  ③ 第二段取消 → 也算这一段结算结束，照样问响应。
	- 第二段（那 1 点法术伤害）改成**攻击牌 / 法术牌完全同一条路**：不再分「自动打行动目标 / 问目标」，
	  统一问一次「两个选项 + 1 名目标」：
	  · 第 1 项「【言灵】为咏类命格或法术牌」—— 这次用的是咏类命格或法术牌才亮；
	  · 第 2 项「额外移除 1 点【秘术】」—— 不是、且还有【秘术】才亮；
	  · 目标头像上显示「1 法术伤害」（技能指示器 8003 加 文案/每目标）；
	  · 可取消：取消＝不对目标造成伤害；两条都不成立时干脆不问。
	- 真言压制（8006）的「你可立即执行一次【真言术】」改成**响应后的白送发动**，不再给额外法术行动：
	  那 1 点法术伤害结算完（`p_harm_end`）→ **不再多问一次「是否发动」**，直接进「哪张言灵 + 打谁」；
	  选定后直接走 `技能出牌()`（不消耗任何行动）。玩家不想发动就点取消；没有可用【言灵】则不发动。
	  原来的 `_真言压制重真言` 标记与「只放行 8003 的额外行动」一并删除。
	- 修：真言压制结算完不触发妖精秘术。原因＝8006 这条选项结算时返回 URGENT（压了伤害），
	  聚合器把「待决」记成 8006；等伤害和多步询问跑完，聚合器带着**空回复**回来续跑，
	  8006 的分支把它当成非法回复（GE_INVALID_ARGUMENT），聚合器于是直接收尾，剩下来的妖精秘术就没被问。
	  现在空回复按「续跑」处理、返回成功，聚合器继续收集剩余选项。
	- 修：真言术 → 真言压制 → 真言术 …… 取消要按很多次。原因是「真言压制白送的那次真言术」
	  每结算一次就再开一轮行动结束响应（聚合器），和外面的待决套娃，取消要一层层退出。
	  现在引擎加了 `技能出牌不开响应`：角色在调 `技能出牌()` 前置 true，这一次出牌只跑 p_action_end
	  （第二段照常结算），不开响应组；外层响应的待决接着继续问，一次取消就能结束整串。

### 4.17 女仆长（81）：影之风的 +1【糸】漏了「拥有【风穴】」门禁

现象：女仆长每次【攻击行动】结束都会 +1【糸】，即使【风穴】根本不在场上（还没被【影之穴】放下来过，或被【风止】移除之后）。

原因：`p_after_attack` 里那句 `player.add_token(糸槽, 1)` 是无条件执行的。同一条技能的另一半
（命中后把攻击牌变成【影】）以及风止、影缝都判了「拥有 / 持有【风穴】」，只有这一句漏了。

修：`p_after_attack` 加上 `if not 拥有风穴(): return SUCCESS`——专属技跟着卡走，风穴不在场上就没有这条被动。

口径对照（和结界师【绝界】不冲突）：
- 【绝界】`owner=结界师、attached=持有者`，三条专属技的「你」是**持有者**，所以代码用 `_绝界持有者()`；
- 【风穴】`owner=女仆长、attached=对手`，专属技的「你」是**女仆长自己**，所以用 `拥有风穴()`（卡在场上）。
两者都是「角色脚本里写钩子 + 场卡做开关」，不是两套结构。

（补充口径：【风穴】不是卡表里的牌，它只是一条「场卡」记录（`engine.加场卡` 由【影之穴】创建、
【风止】移除），所以不存在「在牌库 / 手牌」的中间状态 —— 只有「在场上」与「不在场上」两种。
卡表 `卡表#N` 里查不到它。）

### 4.18 女仆长（81）：禁术·影牢改成「先问是否发动」，第二段延后一拍

1. **+1【糸】不再自动加**：其他角色【特殊行动】结束时先问一次「是否发动【禁术·影牢】」（可取消）；
   选发动才 +1【糸】并播报。第二段（已【横置】且【糸】≥3 → 移除 3【糸】、重置、打 2 / 令队友弃 1）照旧可选可取消。
2. **第二段延后一拍**：`p_after_special` 里加完糸以后只 `push` 一个下一拍的钩子 `p_影牢续` 并返回 SUCCESS，
   等本钩子轮次跑完（引擎只在状态 CONTINUE 时结算指示物变化）把 +1【糸】的播报发出去，
   再由 `p_影牢续` 弹效果 / 目标询问。这样不会再出现「没看到加糸、却已经能移除 3 糸」的画面。

### 4.20 全仓排查：`p_after_special` 会被「启动」技能触发

引擎里「启动」技能（kind = special）结束时也会跑 `p_after_special`，但它的 ctx 只有
`player / kind / is_skill / action_id`，**没有 `special_action`**（真特殊行动＝购买 / 合成 / 提炼才有）。
所以依赖这个钩子的「特殊行动后」技能都要按 `ctx.special_action` 过滤：

| 角色 / 技能 | 钩子 | 结论 |
| --- | --- | --- |
| 女仆长 禁术·影牢 8106 | p_after_special | **会被启动技误触发 → 已加门禁** |
| 圣弓 圣煌模式 3703（形态解除奖励） | p_before_special + p_after_special | before 只对真特殊行动（引擎只在 `_do_special` 调）；after 会被启动技触发 → **已加门禁** |
| 圣弓Trick 8803 | 只有 p_before_special，奖励在 before 里直接结算 | 不受影响 |
| 神官 神圣启示 1501（【特殊行动】结束时 +1【治疗】） | p_after_special | 本来就有 `special_action` 门禁 ✓（引擎里这个脚本就是 role_shenguan.gd，角色号 15） |
| 游击士 附魔之术 | p_after_special | 本来就有 `special_action` 门禁 |
| 巫女 血之哀伤 2303 | p_after_special | 按 `action_id == 2303` 过滤（那是她自己的启动技），真特殊行动 aid 不会撞 |
| 格斗 百式幻龙拳解除 | p_before_special | 只对真特殊行动，不受影响 |

附带发现（本轮未改）：引擎在**校验之前**就调 `p_before_special`（`_do_special` 里先 call_hook 再 `v_buy` / `v_synthesize` / `v_extract`），
所以一次**被驳回**的特殊行动也会触发这个钩子 —— 圣弓会留下「形态解除待选奖励」的标记。加了门禁后它不会在启动技上消费，
但会在下一次真特殊行动结束时补问。要更彻底就把这个钩子挪到校验之后（会同时影响格斗的形态解除）。

### 4.22 盖牌张数变化也写战斗日志

### 4.24 异教徒【放逐】的「返回」点不动

现象：放逐点技能进二级技能栏（摸 6/7/8 三档）后，「返回」点不动，只能选一档发动。

原因：技能指示器 `技能_放逐` 抄了 `"锁定不可取消": true`（那条本来是给「自动选目标＝自己、且没有选项」的技能用的）。
客户端 `_添加返回按钮` 的点击回调里包了一层 `if _取消可用(): 回退.call()`，而 `_取消可用()` 在 mode 4
遇到 `目标锁死 and 锁定不可取消` 会返回 false —— 于是返回按钮看起来在、点了没反应。
放逐的角色脚本本来就写着「不选就按『返回』退出来，不扣能量也不发动」，两边口径冲突。

修：去掉 `技能_放逐` 的 `锁定不可取消`（`自动选目标`/文案保留，额外行动的预览不受影响）。
另外核过：带 `锁定不可取消` 的其它技能都没有 `arg_choices`（mode 4 不会出现返回按钮），
而 3607 / 3406 这类是 mode 3 询问，`_取消可用()` 走的是 `_skill_ask_can_cancel`，不受这条影响。

#### 4.24.1 同类问题排查：「返回」按钮与「锁定不可取消」

判据：mode 4 里既有 `arg_choices`（→ 二级栏会摆「返回」）、又有 `锁定不可取消` + `自动选目标: 自己`
（→ `_目标锁死` → `_取消可用()` 为 false）的技能，「返回」都会点不动。

全仓扫描（const.gd 的 `锁定不可取消` × 各角色 `available_skills` 的 `arg_choices`）命中 6 个：

| 技能 | 结论 |
| --- | --- |
| 1405 判决天平（仲裁者） | 锁定是既有设计（只作用于自己），返回改成显示为不可用 |
| 2304 逆流（血之巫女） | 注释明写「锁定后不许取消」→ 保留锁定，返回显示为不可用 |
| 3406 散华轮舞（血色剑灵） | 注释明写「不许取消」→ 保留锁定，返回显示为不可用 |
| 3607 御魂流居合式（兽灵） | 同上 |
| 3703 圣煌模式（圣弓） | 锁定沿用「只作用于自己」的约定 → 返回显示为不可用 |
| 8803 圣煌模式Trick | 同上 |

处理：
1. 客户端 `_添加返回按钮` 改成**按 `_取消可用()` 决定按钮可用性** —— 不能用时半透明且点击回调为空（说明写「这一步不能返回」），
   不再出现「按钮亮着、点了没反应」。主「取消」按钮本来就是这么处理的（`BtnCancel.disabled`），这次让返回按钮对齐。
2. 9505【放逐】是**锁错了**（角色脚本要求「不选就按返回退出」）→ 已单独去掉它的 `锁定不可取消`（4.24）。

### 4.26 通用「卡牌系别属性」：苍炎魔女【烈焰形态】（按持有者现算）

**机制**（引擎 / 数据层，不含角色特判）：

- 角色可实现两个通用钩子：`BattleRole.牌系别覆盖(card) -> int`（这张牌在我手里时有效系别是多少，0＝不改）
  与 `牌系别属性名() -> String`（写进快照给客户端用）。
- `BattleEngine._check_卡牌属性()` 每拍按**持有者**现算：遍历每名玩家手里（含「盖牌当手牌」）的牌，
  问持有者的角色要覆盖值，写进 `GCard.系别覆盖`（`element_enum()` 优先返回它）。
  所以「别人隔着他的回合塞牌给她」「她摸牌 / 弃牌 / 交牌」都不需要任何额外处理，下一拍自然跟上。
- 牌**离开手**后由同一拍清掉；唯一例外是「这张牌正在某次攻击 / 应战的结算里」（`_牌在结算中`），
  那时应战要求、伤害、表现牌还要读它的系别。
- 属性只写在 `Data.取实例卡(iid)` 的**运行时实例副本**上（牌库里 iid == 牌号，直接改牌面对象会串到同牌面的其它副本）；
  `取实例卡` 新建副本时不继承属性。
- 快照新增 `hand_attrs`（`proto_schema.gd` 字段 41，与 `hands` 一一对应）：客户端据此区分
  「玩家自己切的系别（魔刃/异刃）」与「属性覆盖」，左上角系别标签画成覆盖后的系别。
- 由于覆盖写进 `element_enum()`，同系 / 异系、应战要求、弃牌费用、攻击表现牌、卡面标签全部自动跟着走，
  魔刃 / 异刃不需要任何单独兼容。

**苍炎魔女**（`role_monv.gd`）：

- `牌系别覆盖`：`tap`（烈焰形态）+ 攻击牌 + 自己的系别不是水 / 暗 → 返回火（用 `基础元素()`，所以魔刃/异刃看当前选中的那一系，水系魔刃不受影响）；
- 进入 / 离开形态、摸牌 / 交牌都不需要写任何维护代码；
- **删掉了**原来「改用虚拟【火焰斩】(87)」那套（`p_attack_card` / `p_reattack` / `_fire_slash_card`）：
  现在攻击牌本身就是火系，`card_id` / 命格 / 表现牌都保持真牌。
	- 修两处「属性改过系别，但表现没跟上」：
	  · 卡面左上角元素图标：`CardUI._画命格元素` 原来直接比 `c.element`（牌面自己的系别），改成比
	    `GConst.element_to_string(c.element_enum())`（有效系别）；
	  · 出手音效：`battle_mobile._出手音效` 原来用 `"atk-" + 牌.element`，同样改成有效系别；
	  · 攻击表现牌：`BattleEngine.攻击表现牌` 原来只给魔刃 / 异刃换斩击表现牌，现在「有效系别 != 基础系别」
	    的普通攻击牌也换成该系的表现牌（如火焰斩 87）—— 客户端据此播火斩特效 + 火系攻击音，
	    主动攻击与应战反击都走这一条。
	- 补两个「不依赖每拍缓存」的取用点，调试发牌 / 刚塞进手的牌也能立刻正确：
	  · `BattlePlayer.to_proto` 下发手牌系别时**按持有者现算**（`role.牌系别覆盖(card)`，否则用 `card.基础元素()`），
	    不再读 `GCard.系别覆盖` 的缓存；`hand_attrs` 同理；
	  · `BattleEngine.on_message`（收到行动 / 应答）开头先 `_check_卡牌属性()` 同步一次，
	    这样调试发的牌还没等到状态边界就被当火系用也是对的。
	- 删掉了【烈焰形态】最后两处「攻击 / 应战」相关的角色特判：
	  `p_attack_card`（改用虚拟火焰斩）、`p_reattack`、`_fire_slash_card` 之前已经去掉；
	  这次连 `v_reattack` 也删了 —— 它的逻辑与通用 `base_v_reattack` 完全等价，
	  只剩「暗系攻击的驳回码是 INVALID_CARDID 还是 INVALID_ACTION」的差别，而客户端对错误码统一提示
	  「操作无效，请重新选择」，用户不可见。
	  现在苍炎魔女在攻击 / 应战上没有任何特殊代码，只剩形态本身的 `牌系别覆盖` / `牌系别属性名` 两个通用钩子。

#### 4.26.1 「卡牌系别属性」取用点排查

逐条过了一遍读系别的地方（65 处 `element_enum()` + 所有 `card.element` 直读），本轮补掉两处：

1. **额外行动白名单**（`BattleEngine.额外行动出牌白名单`）：原来按**牌面**（`Data.card_db`）筛系别，
   只对魔刃 / 异刃做了「按实例当前系别」的补丁。所以她被【烈焰形态】视为火的斩，遇到
   「只能用火系攻击牌」的额外行动会被驳回。现在改成：拿着这名玩家的手牌逐张按**实例有效系别 / 命格**
   补进白名单（魔刃/异刃 + 被属性改过的普通牌一并覆盖）。
2. **展示区 / 出牌日志**（`battle_mobile`）：`card_elements` 只在「牌面自己可切换系别」（魔刃/异刃）时才套用，
   别的客户端看到她打出的「风刃斩」时，展示位那张牌的图标还是风。现在有效系别与牌面不同时也按覆盖显示。

确认没问题、不动的：
- 服务端规则侧（应战校验、攻击 harm 的 `card_id`、表现牌、命中判定、出牌白名单的技能 `cards`、
  弃牌费用、`按系攻击牌` 等）读的都是**实例**的 `element_enum()`；
- 应战询问下发 `args[6]` 带着攻击牌的有效系别，客户端应战判定/提示都优先用它（远端客户端没有实例副本也不会错）；
- 快照与指令入口已按持有者现算（见上一节），不依赖每拍缓存；
- 客户端 `_实际系别()` 里的「苍炎魔女 + tap」旧特判与属性结果重复，已删除（连带只有它在用的
  `苍炎魔女角色` 常量）；应战判定直接比 `牌.element_enum()`。
	- 修「烈焰形态下魔刃 / 异刃切换系别像没反应」：
	  · 服务端 `设置卡牌元素` 成功后补一次 `_broadcast_game()` —— 有效系别可能被卡牌系别属性改写过
	    （如视为火），只发 `CardElement` 客户端会停在旧系别；现在按快照里的 `hand_elements / hand_attrs` 重算；
	  · 客户端的切换条选中态改成比 `card.基础元素()`（这张牌自己切到哪一系），图标仍按有效系别 ——
	    异刃（雷/风）在形态下两个系都是「视为火」，图标保持火，但切换条能看出当前选的是雷还是风；
	    魔刃切到水系后有效系别立刻回到水（属性算出来是 0，自动清掉覆盖）。

### 4.27 染污者（83）三处修复

1. **飘字与实伤不一致（飘 2 打 3）**：引擎 `push_harm` 原来是「先广播受伤飘字 / 伤害事件，再跑 ③ 的改伤钩子」，
   而染污者【神弃之裔】/【狂戾形态】的加伤在 `p_timeline_3`，所以飘字拿到的是加伤前的点数。
   现在把 ③ 钩子挪到飘字**之前**（顺序仍是「飘字 → 伤害事件 → 治疗抵御」），
   所有在 ③ 改伤的角色（染污者、格斗家念气力场、圣殿骑士圣炎抵御…）飘字都会是最终值。
2. **狂戾形态下【圣光】没置灰**：只有 `v_block` 服务端兜底，客户端仍会亮、点了才被拒（还会被判成命中）。
   补 `p_attacked`：狂戾形态下把本次攻击 ctx 的 `can_light` 置 false，客户端据此把【圣光】置灰、点不动。
3. **「无法使用【圣光】」改成通用机制**：新增 `BattleRole.能否使用圣光()`（默认 true）。
   引擎在**攻击询问**与**魔弹询问**里都会把 `can_light` 下发成 false（客户端据此把【圣光】置灰、点不动），
   `BattlePlayer.v_block` 也统一拒绝 —— 角色只写一个钩子，不用再各自写 `p_attacked` / `v_block` 两条。
   染污者改成 `能否使用圣光() = not player.tap`（狂戾形态）；魔剑士【暗影抗拒】顺手迁移成同一钩子。
   （圣殿骑士【神威】/兽灵【一击无念】/萝莉番长 9703 的禁圣光是**针对某一次攻击**的 ctx 调整，保持原样。）
4. **狂戾形态的两条加伤都保留**（需求方 2026-11-10 确认）：8303 是「自己造成的伤害 +1」，8304 是「承受伤害时移除 1 戾气、该次伤害 +1（最高 4）」，互不覆盖，代码与说明都不用改。

4. **扭曲之爱改成三段询问**（写法照【军神威光】的两段式：每段一个函数、`_扭曲段` 记段号、
   `p_special_skill` 按段号分派、整条链共用一个倒计时）：形态 → 弃 2 张（当场选牌）/ 摸 2 张 → 调整【戾气】。
   后段「返回」＝重问前一段；第一段取消＝不发动（宝石不扣）；弃的牌先记着，三段选完才结算（中途返回不白弃牌）。
   「返回上一段」不再给技能单独配指示器：`询问()` / `ask_skill()` 新增 `可返回` 参数（下发 `allow_back`），
   客户端据此摆「返回」，任何多段技能都能直接用。技能表 8306 按钮列＝`调整为【普通形态】` / `调整为【狂戾形态】` /
   `你弃 %d 张牌` / `你摸 %d 张牌` / `调整【戾气】为 %d`。
   客户端 `_发送应答` / `_发送行动` 改成「稍等 0.15s 再清界面」：服务端要等引擎下一拍才发下一段询问，
   立刻清空会让界面先退回行动栏再重建（闪一下），连续多段时还会把刚摆好的选项抹掉。
	- 加伤飘字：`_被动改伤` 里三处加伤都补 `notice_skill` ——
	  【神弃之裔】（目标有治疗 +1）、【狂戾之心】（狂戾形态造成伤害 +1）飘在**目标**头上，
	  【狂戾之体】（承受伤害 +1）飘在自己头上（同狂战士【狂化】的做法）。
	- 扭曲之爱三处体验修正：
	  · 「你弃 2 张牌」手牌不足也能选：标题按实际张数写（有多少弃多少，0 张＝空弃），不再置灰；
	  · 确认选项后界面会「闪一下」/「自动退出选项」：`_发送行动` 原来发完无条件 `_清空待选`，
	    而服务端可能在同一帧就把下一段询问递回来（进程内直连），刚摆好的选项被抹掉。
	    改成与 `_发送应答` 同一套「询问代没变才清」的守卫。
	  · 「你弃 2 张牌」的标题固定写 2 张（不随手牌数变成 1/0）；`need_card` 仍给实际要选的张数，
	    手牌不足照样能选、0 张时不用选牌直接确定，结算按 min(2, 手牌数) 弃。
	- 狂戾之心（8303）：**手牌为空也能变身** —— 原来是「没牌就等下次触发」，现在照样询问
	  （need_card 给 0，只选「移除 2 治疗」的目标），没有牌可弃就不弃。
	- 另修一个真 bug：三段都选完、压入「摸 2 张牌」后返回 URGENT，`p_special_skill` 会被再次调用，
	  而那时段号已被清回 0 → 又把第一段问了一遍（表现为选项突然重开 / 像是退出了又进来）。
	  现在结算前置 `_扭曲段 = 扭曲_已完成`，重入直接返回；新一次发动由 `v_special_skill` 清零。
